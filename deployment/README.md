# 源码与部署中心

本目录描述如何从唯一源码生成七个固定角色的版本成品，以及如何把这些角色组合到 1—7 台服务器。它保存“构建和部署规则”，不保存生产数据库、上传素材、真实密钥或正式备份。

## 一、目录规则

| 位置 | 定位 | 是否直接上传服务器 |
|---|---|---|
| [`00-platform-source`](../README.md) | 唯一开发源码 | 否 |
| [`deployment/role-definitions`](./role-definitions/README.md) | 七角色打包白名单、排除项、依赖和回滚规则 | 作为构建规则使用 |
| [`deployment/profiles`](./profiles/README.md) | 1—7 台服务器与角色映射 | 作为部署计划使用 |
| [`deployment/common/global-release-flow.yaml`](./common/global-release-flow.yaml) | 全局六步发布流程 | 作为流程规则使用 |
| 外层 `01`—`07` | 角色交付工作区和未来版本成品目录 | 只上传已审核的目标版本成品 |
| 外层 `local-data` / `local-runtime` | 本机数据和可重建运行时 | 禁止 |

目录迁移后由当前工作区根和 PathRegistry 解析实际路径。规则文件只使用相对路径，不以某个盘符作为事实源。

## 二、七个角色规则

七个角色的职责、依赖和成品目录见 [七角色规则](./role-definitions/README.md)。机器可读事实源是 `role-01.yaml` 至 `role-07.yaml`；README 和页面只展示这些规则，不另建手工副本。

## 三、发布包结构

角色成品的逻辑位置固定为：

```text
<工作区根>/<01—07角色目录>/releases/<version>/
└─ 经审核的不可变角色成品
   ├─ 本角色运行产物或镜像引用
   ├─ manifest、源码版本和 SHA-256 校验值
   ├─ 环境变量模板与依赖说明
   ├─ 启动及健康检查说明
   └─ 上一版本回滚说明
```

实际构建器必须以角色 YAML 的 `sourceIncludes`、`sourceExcludes` 和 `artifactRoot` 为准。当前发布计划生成器只输出 dry-run JSON，不会创建上述目录、复制文件、读取密钥、连接服务器或上传成品：

```powershell
python deployment/scripts/generate-release-plan.py 3 2026.08.18.1
```

## 四、完整发布流程

六步流程的唯一机器事实源是 [`global-release-flow.yaml`](./common/global-release-flow.yaml)：

1. 发布预检
2. 选择服务器方案
3. 生成角色包
4. 查看影响
5. 发布部署
6. 健康检查与回滚

每一步的输入、动作、输出、门禁和回滚方式均从该文件读取。生产操作细节见 [RUNBOOK.md](./RUNBOOK.md)。

## 五、1—7 台服务器组合

| 台数 | 角色放置摘要 | 灾备边界 |
|---:|---|---|
| 1 | `01`—`06` 合并 | 必须使用服务器外部备份目标 |
| 2 | `01`—`05` 应用；`06` 数据 | 必须使用服务器外部备份目标 |
| 3 | `01/02/03/05`；`04`；`06` | 必须使用服务器外部备份目标 |
| 4 | `01/02/03`；`04`；`05`；`06` | 必须使用服务器外部备份目标 |
| 5 | `01`；`02/03`；`04`；`05`；`06` | 必须使用服务器外部备份目标 |
| 6 | `01`、`02`、`03`、`04`、`05`、`06` 分离 | 必须使用服务器外部备份目标 |
| 7 | 六个生产角色分离并增加独立 `07` | `07` 必须位于不同凭据和故障域 |

完整服务器 ID、角色数组和用途只维护在 [`profiles/01-server.yaml` 至 `07-server.yaml`](./profiles/README.md)。扩容只改变角色放置，不复制源码，也不改变租户、客户、计划或数据库标识。

## 六、必须固定的管理原则

1. `00-platform-source` 永远是唯一可编辑源码。
2. 外层 `01`—`07` 只保存角色说明、交付元数据和不可变版本成品。
3. 正式构建只收集角色白名单，排除数据、素材、缓存、日志、密钥和备份。
4. 同一版本号必须对应同一源码提交、manifest 和校验值。
5. 发布前必须通过源码锁、类型、共享契约、租户隔离、迁移和恢复点检查。
6. 数据库迁移先于依赖它的应用，并附迁移专用回滚或隔离恢复说明。
7. 服务器只接收所选 profile 需要的角色版本，不上传整套源码。
8. 生产配置通过环境或密钥管理注入，不写入发布包。
9. 发布包构建后禁止在服务器上直接修改；修复必须回到唯一源码重新发布。
10. 上一程序版本保留到健康检查、业务冒烟和恢复证据全部通过。
11. `local-data` 的备份暂存不等于正式异地备份。
12. 路径变化由工作区根和 PathRegistry 处理，禁止重新写死盘符。
