# HR人事中心运营契约

## 业务定位

HR人事中心是组织、岗位、员工身份、劳动关系、工时、绩效与培训能力的业务权威，负责把“需要什么岗位、谁在岗、依据什么合同工作、投入多少时间、能力是否达标”连接到工厂的真实经营能力。它不接管招聘过程、工资核算、财务付款或营销客户数据：招聘与AI面试由招聘中心负责，实际工资金额与发放由薪酬/财务系统负责，营销联系人和客户画像绝不导入员工主档。

平台只保存履职所需的最小数据，包括工作身份、国家、组织岗位、合同日期、工时、薪酬等级与外部工资编号。原始银行卡号、税务申报、健康诊断、身份证扫描件和具体工资金额不进入本模块；敏感原件留在有法定保管能力的专用系统，以引用和审批证据连接。

## 组织、岗位与员工主档

组织状态为 `draft → active`，作者不能审批自己的组织。组织可以引用已启用的ERP经营组织，但不复制ERP账簿、成本或记账数据。父组织必须先启用，国家与时区必须明确。岗位建立在已启用组织下，保存岗位族、等级、规划编制、周产能与关键岗位标志，用于人员缺口和产能分析。

员工主档状态为 `draft → active`，创建来源只允许 `hr-direct`、`recruiting-offer` 或 `migration`。工作邮箱、员工参考号和隐私告知证据为必填；激活人必须与作者不同。CRM线索、广告受众、社交账号和客户联系人不能成为员工来源。

## 劳动合同与岗位任用

劳动合同状态为 `draft → pending-approval → active`。合同必须连接已激活员工与有效岗位，保存任用类型、工作地、起止日期、每周工时、薪酬等级、工资系统引用和签署文件引用。合同作者不能批准自己的合同，同一员工不能同时拥有两份有效合同。

合同只声明就业关系和岗位任用，不保存工资金额，也不向ERP、财务或工资系统回写虚构数据。实际薪资计算、个税、社保、公积金、银行代发和会计凭证仍由法定薪酬与财务系统负责。

## 工时、绩效与培训

月度工时状态为 `draft → submitted → approved`。计划工时、实际工时、批准休假和加班必须满足容量勾稽，作者不能批准自己的工时。批准后的工时可以作为薪酬和产能接口证据，但不能自行生成工资或财务凭证。

绩效状态为 `draft → calibrated`。评价必须连接有效合同，保存目标分、能力分、证据和经理评语，综合分按受控规则计算；评价作者不能完成自己的校准。绩效结果用于人才发展与经营复盘，不得自动触发解雇、降薪等高影响决定。

培训状态为 `assigned → completed → verified`。必修课程必须有未来截止日，完成时登记LMS或证照证据，核验人必须与完成登记人不同。关键指标包括在职人数、规划编制、关键岗位到位率和必修培训合规率。

## 权限、审计与三端边界

权限拆分为主档管理/审批、合同管理/审批、工时管理/审批、绩效管理/校准、培训管理/核验十项。所有记录携带 `agent_path`、`tenant_id`、`client_id`、`project_id` 和 `plan_id`；每次状态变更同时写业务证据与带 `project_id` 的平台审计，并使用修订号阻断陈旧写入。

- 总部端：维护全球人事词典、隐私最小化规则、职责分离与国家包边界。
- 代理端：只能在获授权客户计划中实施配置或承担被授权的独立复核，不能跨租户查看员工数据。
- 客户端：录入真实组织、岗位和员工事实，承担合同、工时、绩效及培训证据的合法性与最终责任。

## 迁移与回滚

回滚只删除HR人事中心拥有的记录与权限，不删除或修改ERP、财务、招聘、薪酬、营销联系人和客户画像。生产回滚前必须导出所有有效劳动关系、法定工时和培训合规记录，并确认下游薪酬、门禁、排班及合规系统不再依赖本模块记录ID。

## 上线验收

上线前必须证明：组织与员工主档不能自批；营销联系人不能导入员工主档；合同必须连接有效员工与岗位且不能重叠；原始银行卡、税务、健康和工资金额不落库；工时容量能够勾稽且独立审批；绩效独立校准；培训完成证据独立核验；租户隔离、权限、证据、修订冲突和带项目ID的审计成立；迁移升级、降级、再升级、生产构建、双角色真实API闭环及真实页面验收全部通过。
