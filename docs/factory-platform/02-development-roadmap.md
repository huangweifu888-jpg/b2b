# P0/P1/P2 开发路线图

本路线图与 `frontend/src/lib/factory-platform-blueprint.ts` 的三个程序阶段一一对应：

| 路线图 | 程序 phase | 阶段名称 | 核心目标 |
| --- | --- | --- | --- |
| P0 | `revenue-loop` | 收入闭环 | 先跑通经营治理、身份内容、搜索社交、授权画像、付费获客、询盘报价、客户经营和基础决策 |
| P1 | `manufacturing-loop` | 制造履约闭环 | 把订单意向连接到确认订单、产品工程、供应、制造、质量、仓储、物流、售后和人力协同 |
| P2 | `global-intelligence` | 全球智能增长 | 在稳定事实数据上扩展GEO、跨国内容、深度洞察、智能投放、客户预测和AI决策 |

## 阶段判定规则

1. **以应用的 `phase` 为准**：同一类别可跨P0/P1/P2，不能只看类别默认阶段推断全部应用的交付时间。
2. **阶段不等于可售状态**：P0/P1/P2是建设顺序；“已具备、试点、规划”由程序能力注册和发布状态单独标识。
3. **准备依赖不等于应用已完成**：后续阶段应用所需的数据契约、事件和适配接口可以提前建设，但不得因此宣称该应用已具备。
4. **进入下一阶段不停止前一阶段治理**：租户隔离、审计、事实源、监控、回退和验收持续适用于全部阶段。

## P0：收入闭环

### 建设范围

1. **经营和财务底座**
   - 建立组织、工厂、项目、成本中心、角色、审批、合同和主数据治理。
   - 跑通应收应付、财务状态、实际成本、利润和现金的授权副本或ERP Lite路径。
   - 12.固本不确认订单；它只消费09或外部权威OMS/ERP返回的确认订单标识做财务过账。
2. **身份、内容和搜索信任**
   - 从产品分析、市场机会、ICP和品牌规范生成多站点、企业资料、产品内容及证据页面。
   - 建立技术SEO、关键词、页面规则和企业信任资产的可追溯发布。
3. **社交信号、画像和获客**
   - 先建立社媒账号、内容日历和社群，再将合法采集的互动事件进入06画像。
   - 06在投放前提供分群和触达同意，07只能激活获准受众；06同时持续接收广告、询盘、成交和服务事件。
4. **询盘、报价和客户经营**
   - 跑通全渠道询盘、分配、RFQ/样品、CPQ报价和电子合同。
   - 08输出待确认订单；P0通过现有ERP/OMS适配或最小确认订单契约取得09的权威确认结果，不将08或12当成确认订单主系统。
   - CRM消费06统一客户ID管理关系和行动，不复制客户身份或同意记录。
5. **基础决策闭环**
   - 建立数据仓库、指标语义和健康驾舱，保留租户、来源、时间、口径和血缘。
   - 分析只生成下钻和责任任务，不直接写回订单、客户或财务事实。

### P0依赖

- 即使09的六个完整应用位于P1，P0也必须先冻结确认订单、产品、库存和履约事件契约。
- 接入现有ERP/OMS时，由适配器将外部确认订单映射到09的领域标识；未获得权威确认前只显示“待确认”。
- 个人触达同意由06管理；12只发布隐私政策、合法依据、保留制度、角色和审计规则。

### P0验收门槛

- 37个P0应用分别显示程序状态，规划项不得以可用入口对客户承诺。
- 一条链路可从身份/内容、合法触达、询盘、报价追溯到权威确认订单和财务状态。
- 每条确认订单都有09或外部权威OMS/ERP标识；08和12不存在竞争性订单确认状态。
- 工程标准成本和财务实际成本分别带来源、版本、币种、时间和口径。
- 客户身份、触达同意、CRM行动及分析指标可关联但各自只有一个事实源。
- 三端发布和回退不覆盖客户、订单、内容、素材、同意记录或本地锁定配置。

## P1：制造履约闭环

### 建设范围

1. **产品与供应**
   - 建立PLM产品工程、BOM、工艺版本和工程标准成本。
   - 建立SRM供应商、采购询价、交期和质量协同。
2. **计划与制造**
   - 通过S&OP/MRP/APS连接需求、物料、产能、库存和排产。
   - 通过MES和QMS记录工单、报工、设备、批次、检验、放行和质量整改。
3. **订单确认与全球交付**
   - OMS在产品、信用/付款条件、库存和产能校验后认定确认订单。
   - WMS/TMS管理库存、仓储、报关、运输和签收；原始第三方回执保持可追溯。
4. **交易和售后协同**
   - 上线B2B订货与B2C结账，但结账请求仍须进入09确认。
   - 工单、SLA、质保和RMA连接批次、物流、质量及财务冲销。
5. **组织协同**
   - 上线HR人事和招聘与AI面试，保留人工决定、权限和审计。

### P1验收门槛

- 11个P1应用分别通过功能、权限、事件、对账、回退和容量验收。
- 确认订单可追到产品版本、BOM、计划、工单、批次、检验、库存、发运和签收。
- 标准成本来自09，实际成本和正式利润来自12；抽样订单可以解释二者差异。
- 订单变更、库存预留、质量放行、RMA和财务冲销均幂等且有审批和补偿路径。
- 国内B2B、国内B2C及至少一个海外试点使用同一订单内核并通过租户隔离。

## P2：全球智能增长

### 建设范围

1. **全球内容、搜索和推荐**
   - 建立竞品价格、DAM本地化、排名份额、口碑公关、GEO/AEO、知识图谱、事实库、引用监测、结构化数据和平台Feed。
   - AI和渠道只消费获批事实，不以生成内容反向覆盖工程、证照或客户主档。
2. **深度社交和智能投放**
   - 建立AI本地化、社交聆听、KOL/直播、AI创意、投放实验和预算归因。
   - 所有受众激活继续受06同意和用途限制；归因不是财务会计事实。
3. **客户和售前智能**
   - 建立AI售前、身份合并、B2B企业关系图、客户成功和续约增购。
   - AI建议、健康分和复购预测只创建人工可复核的行动。
4. **经营智能**
   - 建立收入利润、需求产能现金预测和AI战情中心。
   - 模型输出带事实来源、口径、时间、权限和责任任务，不直接写回主事实。

### P2验收门槛

- 24个P2应用分别显示已具备、试点或规划状态，并绑定对应验收证据。
- 国内/海外、B2B/B2C共享核心对象，仅通过国家、渠道和模式配置表达差异。
- GEO、引用、排名、广告、归因和AI指标均注明平台、模型、时间、样本和不确定性。
- AI输出可追到授权事实、人工复核、审批/否决和最终行动结果。
- 增长预算可关联到权威确认订单、财务实际毛利、现金和客户LTV，但不宣称单一动作保证增长。

## 阶段变更与状态治理

- 调整应用 `phase` 时，必须同步修改程序契约、本文矩阵、依赖、验收和门禁；不得只改文档。
- 路线图项目只有在代码、配置、文档、权限、监控、回退和验收证据齐全后，才能由程序标记“已具备”。
- “试点”必须声明客户/区域白名单、期限、限制、支持责任和退出方案。
- 未进入程序能力注册或未完成证据门禁的应用一律按“规划”处理。
