# 02.布场（内容）｜全球 B2B/B2C 多站多语言体验规范

## 0. 规范定位

本规范把 `02.布场(内容)` 从“维护网页栏目”升级为工厂全球获客与转化的内容操作系统：同一份经过核验的企业、产品和证明内容，按市场、语言、客户类型与站点目的，生成可审计、可预览、可回滚的网站体验。

它覆盖国内 B2B、海外 B2B、国内/跨境 B2C 品牌与交易前站；不把 B2B 与 B2C 做成两套孤岛系统。两者共用产品事实、企业事实、素材、品牌资产、术语与合规边界，只在价格展示、购买动作、询盘路径、会员及库存/订单消费方式上分叉。

本文件是下一阶段的**设计和实施规范**，不改变既有 72 个应用的 `deliveryStatus`，也不把未来注册商、翻译引擎或外部发布能力虚称为已自动接入。

## 1. 客户价值与商业主张

客户购买的不是一个建站器，而是一套“从工厂事实到全球成交页面”的连续生产线：

`产品/企业事实 → 品牌与营销策略 → 页面组合 → 语言与区域版本 → 审核预览 → 受控发布 → 询盘/交易 → 数据回流`。

对工厂的直接价值：

- 国内经销、海外采购、终端消费者看到的内容既因市场而异，又不会出现规格、资质、品牌口径互相矛盾。
- 一个产品、案例、视频或资质可复用到品牌官网、国家站、活动落地页、B2B 询盘页和 B2C 商品落地页，减少重复建站和翻译返工。
- 人工可以改每一种语言的营销表达；机器翻译只提速，不能绕过术语、合规和人工审核直接上线。
- 站点结构、域名、模板、发布版本和销售转化可追溯，代理/客户修改不会反向覆盖总部或其他客户。

## 2. 信息架构：一个内容核，四类站点

### 2.1 站点类型

| 站点类型 | 主要对象 | 首要动作 | 必有页面/组件 |
| --- | --- | --- | --- |
| 品牌官网 | 国内外采购商、合作伙伴 | 建立信任、提交询盘 | 首页、企业实力、产品、案例、资质、联系 |
| B2B 行业/国家站 | ICP、采购委员会、工程商 | 找规格、下载资料、询价/预约 | 行业方案、产品详情、应用案例、技术资料、询盘表单 |
| B2C 品牌/商品站 | 终端消费者、零售商 | 了解、加购或跳转交易 | 商品故事、卖点、评价/保障、FAQ、购买入口 |
| 活动/渠道落地页 | 广告、展会、社媒流量 | 单一转化 | 价值主张、证明、表单/预约、追踪与归因 |

同一 `site_space` 可以有多个市场版本；页面必须标注 `audience_mode = b2b | b2c | hybrid`，不允许用复制页面的方式把同一事实分裂成无来源的多份文案。

### 2.2 B2B/B2C 差异只存在于体验层

- B2B：默认展示 MOQ、定制能力、证书、规格、交期范围、下载/询盘/样品/报价入口；正式报价、合同、库存与交期仍由 08/09/12 类权威域确认。
- B2C：默认展示价格可见性、商品卖点、服务承诺、评价和结算入口；价格、库存、促销、订单与支付仍由 `commerce` / ERP / OMS 权威系统确认。
- `hybrid`：先让访问者选择“采购/经销/终端购买”意图，再投影不同 CTA；不得把消费者价格误当作 B2B 报价。

## 3. 六项核心能力规范

### 3.1 自适应与无障碍

所有页面、模块、弹窗和可视化编辑器必须以同一组件契约覆盖手机、平板、桌面：

- 编辑画布提供 `mobile / tablet / desktop` 三种预览，保存的是同一个页面版本及断点规则，而不是三个互相漂移的页面副本。
- 首屏、导航、CTA、表单、图表与视频在窄屏无横向溢出；触控目标不小于 44px；键盘可操作；图片含替代文本；颜色对比与语言方向（LTR/RTL）可测试。
- 响应式变更须产出页面差异、受影响断点和恢复点；禁止为局部页面写绕开共享框架的样式覆盖。

### 3.2 可视化编辑与页面模型

可视化编辑器采用“区块化页面 + 受保护事实字段”模型：

- 页面由 `Page → Section → Block → Binding` 构成；区块可拖拽、复制、隐藏、按市场替换，字段绑定到企业、产品、案例、媒体或翻译内容。
- 编辑器支持草稿、预览、对比、评论、版本回滚和发布影响预演；每一次保存记录作者、来源版本、断点、市场、语言与哈希。
- 产品规格、资质有效期、价格、库存、订单等权威事实只读绑定；编辑器可选择展示方式，不能直接改写其主数据。
- 模板有四层：`品牌基础模板 → 站点模板 → 市场/语言变体 → 页面局部覆盖`。覆盖必须是显式补丁，源模板升级不覆盖客户已批准内容。

### 3.3 自动翻译、多语言与人工改稿

语言对象采用 BCP-47：例如 `zh-CN`、`zh-HK`、`en-US`、`en-GB`、`ja-JP`、`ar-SA`；市场使用 ISO 国家/地区码，不以“英文版”笼统代替市场版本。

翻译流程为：

`源语言版本冻结 → 术语/禁译词/品牌语气校验 → AI 初译 → 人工修改 → 母语或区域复核 → 预览 → 发布`。

- 后台语言切换必须在同一页面结构中展示“源文、机器建议、人工稿、已发布稿、差异和状态”；人工可逐段覆盖而不破坏源文。
- 翻译记忆与术语库按租户、品牌、产品线和语言版本隔离；术语版本固定后才可进入翻译任务。
- AI 不能批准自己的译文，不能自动发布；任何缺译、过期译文、术语漂移、RTL 布局失败或区域必填字段缺失均阻断发布。
- SEO 元数据、结构化数据、图片 alt、URL slug、表单和邮件模板均进入本地化清单，不能只翻正文。

### 3.4 前域与后域：`hk.sdsd.com` 与 `sdsd.com/hk`

平台支持两种等价的市场路由策略，并要求一个站点空间只能有一个主策略：

| 策略 | 示例 | 适用 | 强制规则 |
| --- | --- | --- | --- |
| 子域前域 | `hk.sdsd.com` | 地区独立品牌、地区团队、独立 CDN/法律要求 | 主域、TLS、DNS 验证、canonical、hreflang、站点映射独立记录 |
| 路径后域 | `sdsd.com/hk` | 统一品牌和 SEO 资产、中央运营 | 根站与区域路径同一主域，强制路径前缀、canonical、hreflang 与语言切换映射 |

- `market_route` 必须记录 `hostname`、`path_prefix`、`locale`、`market`、`site_space_id`、`canonical_url`、发布版本和生效状态。
- 页面 URL 不得同时在子域和路径策略下可索引；切换策略要生成 301/308 映射清单、canonical/hreflang 影响报告、回滚时间窗与审批记录。
- 域名/路径不代表数据租户边界；所有内容读写仍以 `tenant_id + client_id + plan_id + project_id` 进行权限判断。

### 3.5 数字资产 → 智能命令沙盘

`identity.digital-assets` 提供“命令式建站沙盘”，但其职责是生成可审阅方案，而不是直接改站：

`自然语言目标 → 结构建议 → 影响清单 → 沙盘预览 → 人工选择 → 生成页面补丁 → 审核/发布`。

示例命令：

- “为香港工业采购商创建英文+繁体中文的医疗器械询盘落地页。”
- “将此品牌站改为高信任 B2B 风格，保留现有产品与案例。”
- “为该 B2C 商品增加对比、保障、FAQ 与购买入口，但不改价格和库存。”

沙盘输出必须包含拟新增/删除/移动的页面和区块、涉及语言、绑定事实、SEO 路由、预估风险、来源版本及可撤销补丁。命令不得自动删除受保护栏目、自动购买/转移域名、自动修改正式价格库存，也不得绕过页面锁定器和审批链。

### 3.6 品牌风格与营销/品牌页切换

`identity.brand` 输出版本化 `brand_system`：标志、色彩、字体、版式密度、图像语气、语调、CTA 风格、组件令牌和禁用用法。

- “品牌型”页面突出信任、长期价值、制造实力、案例和品牌故事；“营销型”页面突出单一人群、单一痛点、证明、CTA 与归因。
- 切换的是页面方案/模板包，不是用 CSS 粗暴替换所有内容；在汇总单页可以显示品牌方案、营销方案及转化目标的对比预览。
- 风格包只作用于允许继承的令牌和区块；客户锁定的标志、法律文本、已发布页面局部覆盖和内容事实不被覆盖。

## 4. 三端同步：源体、计划与运行端

统一生命周期：

```text
总部标准（HQ）
  → 客户源/计划源：可发布的内容、组件、模板与风格基线
  → 客户端/计划端：站点运行快照与允许的局部覆盖
  → 预览/测试：版本差异、链接、语言、断点、SEO 与表单验证
  → 审批发布：按站点、市场、语言灰度
  → 运行回执：访问、询盘、交易入口、错误与回滚证据
```

同步规则：

1. 总部发布的是版本化能力和模板基线，不覆盖客户的业务数据、已批准翻译和显式锁定的局部覆盖。
2. 客户源维护可复用默认；计划源在引用默认的同时保存自己的覆盖清单；计划端只运行已经审批的快照。
3. 每次同步必须给出差异：新增模块、更新令牌、失效绑定、语言影响、路由影响、锁定冲突和回滚点。
4. 三端同读 `factory-platform-blueprint`、内容保护栏目、页面锁定器和共享样式契约；不得再建立独立栏目/路由副本。
5. 测试环境以真实发布包的只读副本运行，不能把测试表单、跟踪或翻译数据写回生产站点。

## 5. 域名与注册商接入：Shopify 式简单，企业级受控

域名中心提供统一体验：搜索/登记、续费提醒、DNS 验证、站点绑定、转入/转出进度、授权码状态、到期风险和审计证据。首批连接器可覆盖阿里云、腾讯云、GoDaddy，并预留 Cloudflare、Namecheap 等适配器。

统一连接器接口：

```text
RegistrarAdapter
  searchAvailability(query)
  quoteRegistration(domain, term, currency)
  createCheckoutIntent(quoteReference)
  verifyDns(domain, expectedRecords)
  requestTransferOut(domain)
  getTransferStatus(transferReference)
  listExpirations(accountReference)
```

硬性边界：

- 注册商密钥仅进入独立密钥保管系统；业务数据库、审计日志、前端状态和导出文件绝不保存密钥或授权码明文。
- 购买、自动续费扣款、DNS 生效、域名绑定和转出均为外部有状态动作：必须显示成本、影响站点、目标账户和确认页，并由具备权限的人提交。
- 平台负责统一工作流和证据，不冒充注册商；注册失败、地区限制、实名/ICANN 审核和转移锁必须如实呈现。
- 转出不会自动解除网站、邮箱、CDN 或 SSL 绑定；必须先提供依赖清单和恢复计划。

## 6. 数据对象、事件和权限

### 6.1 新增/扩展对象

| 对象 | 关键字段 |
| --- | --- |
| `SiteSpace` | 租户、计划、站点类型、主策略、品牌系统版本、运行版本 |
| `MarketRoute` | 主机名、路径前缀、地区、语言、canonical、发布状态 |
| `PageCompositionVersion` | 页面树、区块、绑定、断点、来源哈希、补丁链 |
| `LocalizedPageVariant` | 页面版本、语言、市场、源文哈希、译稿状态、审核结论 |
| `TranslationMemoryEntry` / `GlossaryVersion` | 范围、语言对、术语/禁译词、版本、权利与审核 |
| `BrandSystemVersion` | 风格令牌、模板包、营销/品牌方案、兼容范围 |
| `SiteSandboxProposal` | 命令、受影响对象、差异、风险、预览、批准状态 |
| `RegistrarConnection` / `DomainOperation` | 注册商引用、密钥引用、域名操作、外部回执、审计链 |

所有对象必须携带：`tenant_id`、`client_id`、`plan_id`、`project_id`、`agent_path`、`version`、`created_by`、`created_at`。跨租户、跨计划、跨客户读取一律拒绝。

### 6.2 最小事件

- `page-composition-proposed` / `page-composition-approved` / `site-version-released`
- `localized-variant-submitted` / `localized-variant-reviewed` / `localized-variant-published`
- `market-route-validated` / `market-route-released`
- `brand-system-applied`
- `site-sandbox-proposed` / `site-sandbox-approved`
- `domain-operation-requested` / `domain-operation-acknowledged`

事件须固定对象版本和来源哈希；发布者、翻译复核者、路由批准者和外部回执登记者不可与对应发起人相同。

## 7. 开发顺序与验收门禁

### P0：全球内容底座

1. 补齐 `SiteSpace / MarketRoute / PageCompositionVersion / LocalizedPageVariant` 数据模型、项目权限、审计和迁移回滚说明。
2. 落地响应式可视化页面编辑、草稿/预览/差异/回滚和 B2B/B2C 模板包。
3. 落地语言、术语、人工改稿、机器建议和发布前本地化校验。
4. 让客户源 → 计划源 → 计划端 → 测试环境使用同一发布包与差异报告。

### P1：市场路由与智能沙盘

5. 落地子域/路径策略、canonical/hreflang、策略迁移和 SEO 路由回滚。
6. 落地品牌系统版本与品牌型/营销型页面方案切换。
7. 落地仅生成补丁的 AI 命令沙盘、影响预览、异人审批与可撤销执行。

### P2：注册商连接器和商业扩展

8. 先以“登记、DNS 验证、转出流程回执”接入注册商；再逐家评估查询、报价、支付和购买能力。
9. 与 commerce、CRM、广告归因、GEO、DAM 和 ERP 建立只读/受控事件交接，形成内容到成交的数据闭环。

### 每项能力上线前必须通过

- 数据模型、租户/项目权限、审计、对象与事件契约、迁移升级/回滚演练。
- TypeScript、自动化单元/API/端到端测试、生产构建、真实手机/平板/桌面页面验收。
- 至少验证 `zh-CN + en-US + 一种 RTL 或 CJK 语言`，以及一个 B2B、一个 B2C、一个混合页面。
- 验证子域和路径策略各一条，含 canonical、hreflang、语言切换、404/重定向与回滚。
- 验证机器翻译无法直发、人工不能自审、AI 沙盘不能越权改站、注册商操作必须二次确认。

## 8. 首批可演示的客户场景

1. **国内工厂出海 B2B**：中文主站 + `en-US` 海外询盘站；同一产品规格和证书，英文营销文案人工复核，客户从 LinkedIn/Google 落地到询盘。
2. **香港/东南亚双路由**：比较 `hk.example.com` 与 `example.com/hk` 两种方案，显示 SEO、语言、页面和切换成本，再审批其一。
3. **品牌 + 商品双线**：品牌官网采用信任型方案；某产品活动页采用营销型 B2C 方案，商品购买仅跳转权威商城，不改写价格库存。
4. **AI 改版沙盘**：输入“面向德国工业买家”，生成页面结构、德语任务、术语提醒、路由建议和风险清单；人工批准后才形成可发布补丁。

## 9. 不可妥协的禁止项

- 不把机器翻译、AI 命令或模板同步直接等同于发布。
- 不因切换风格、同步模板或测试环境而覆盖客户内容、价格、库存、订单、法律文本、域名或受保护栏目。
- 不在浏览器、本地配置或普通业务库保存注册商密钥、授权码明文和支付凭证。
- 不把外部注册商、CDN、DNS、支付、ERP 或商城的成功回执伪造为本平台已完成的事实。
- 不为赶进度新增与平台蓝图、栏目配置、运营市场、左侧导航、页面锁定器不一致的第二套栏目、路由或样式规则。
