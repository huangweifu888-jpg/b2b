# 应用立项契约与持续交付流程

所有新应用、重大功能和跨类改造必须使用同一立项契约并依次通过七道门禁。缺少必填字段、责任人、回退或证据时，不得以排期紧张为由跳门。

程序事实源为 `FACTORY_PLATFORM_APPLICATION_CONTRACT_FIELDS` 与 `FACTORY_PLATFORM_DEVELOPMENT_GATES`。

## 十五个必填字段

| 字段 | 需要回答的问题 | 最迟完成门禁 |
| --- | --- | --- |
| 服务对象 | 谁购买、谁使用、谁审批、谁受影响 | 立项评审 |
| 客户问题 | 当前损失、触发场景、不开发后果是什么 | 立项评审 |
| 输入数据 | 数据对象、来源、质量、频率、事实源是什么 | 契约冻结 |
| 输出结果 | 产生状态、事件、文件、任务还是指标 | 契约冻结 |
| 上游应用 | 依赖什么版本，失败如何处理 | 契约冻结 |
| 下游应用 | 谁消费，变更影响和兼容范围是什么 | 契约冻结 |
| 业务负责 | 谁对业务、产品、技术和运营结果负责 | 立项评审 |
| 权限范围 | 租户、角色、字段、动作、跨境边界是什么 | 安全评审 |
| 成功指标 | 基线、目标、周期、口径、负责人是什么 | 立项评审 |
| 客户证据 | 用什么版本、范围、样本和授权证明结果 | 业务验收 |
| 所属套餐 | 属于哪个套餐或增值包，如何降级 | 立项评审 |
| 计费方式 | 按订阅、席位、用量、交易还是实施计费 | 立项评审 |
| 实施周期 | 准备、配置、迁移、培训、试点和验收多久 | 开发验收 |
| 成熟状态 | 规划、试点、已具备及其证据是什么 | 发布准备 |
| 验收标准 | 功能、权限、数据、性能、监控、回退和价值如何验收 | 业务验收 |

## 七道门禁

1. **立项评审**：确认客户问题、负责人、范围、套餐和价值基线。
2. **契约冻结**：冻结领域对象、接口、事件、事实源、上下游影响和兼容方案。
3. **安全评审**：完成租户、权限、隐私、跨境、AI、高风险动作与审计评估。
4. **开发验收**：完成实现、测试、迁移、监控、文档、回滚和三端配置。
5. **业务验收**：以真实角色和数据验证端到端流程、指标口径和异常处理。
6. **发布准备**：完成差异预演、灰度、恢复点、支持责任和销售口径。
7. **价值复盘**：用上线前后事实决定推广、优化、降级、续费或停止。

## 交付状态升级规则

- 立项通过后仍为规划。
- 完成契约、安全、开发和业务验收，并有明确白名单后，才可进入试点。
- 试点达到质量、价值、支持和回退门槛，且绑定正式版本后，才可标记已具备。
- 任一重大回归、合规变化或证据失效都可以降级为试点或规划。

## 每个开发任务的最小交付包

- 程序契约和影响图
- 代码、类型和自动测试
- 数据迁移及回滚说明
- 权限、审计和数据保留策略
- 监控、告警和运行手册
- 页面、接口和用户说明
- 验收用例与证据
- 三端发布、灰度和恢复方案
- 销售可说、不可说边界
- 价值复盘负责人和日期

任一最小交付项缺失时，构建门禁或发布审批必须记录阻断原因，不允许以文档中的“规划”替代真实实现。
