# 核心对象与事件字典规范

对象与事件字典是十二类应用互通的公共语言。蓝图定义源为 `FACTORY_PLATFORM_CORE_OBJECTS`、`FACTORY_PLATFORM_CORE_EVENTS` 与 `FACTORY_PLATFORM_EVENT_REQUIRED_FIELDS`；可运营注册表由 `factory_core_object_contracts`、`factory_core_event_contracts` 和 `/api/v1/factory-platform/contracts` 提供。

注册表只允许总部管理员访问。所有更新使用 `expected_revision` 防止并发覆盖，并写入操作者与审计事件；本地开发可恢复回环地址的总部演示会话，正式环境仍使用OIDC。数据库迁移为 `a2c4e6f8b013`，回滚只移除总部契约定义，不删除租户业务对象或已发生事件。

## 核心对象范围

当前22个对象：组织、员工、企业客户、联系人、产品、规格单元、内容资产、营销活动、询盘、商机、报价、合同、确认订单、物料清单、生产批次、库存、发运、发票、回款、客户资产、服务工单和产品护照。

每个对象必须声明：

- 稳定对象ID和中文名称
- 唯一事实源类别
- 身份合并或版本规则
- 租户边界
- 最小字段
- 创建、更新、归档和清退事件
- 允许读取与写入的角色

## 关键事件范围

当前14个事件：询盘创建、报价提交、报价接受、订单确认、生产完成、质量放行、货物签收、发票开具、回款完成、资产建档、服务完成、保修到期、工程版本发布和产品护照发布。

每个事件统一携带：`eventId`、`tenantId`、`eventType`、`occurredAt`、`source`、`subjectId`、`version`、`correlationId`。

## 事件规则

1. 事件表示已经发生的事实，不能使用将来时或含糊状态。
2. 同一业务动作的重复投递必须通过 `eventId` 或幂等键去重。
3. `occurredAt` 表示业务发生时间，接收时间另行记录，不得混用。
4. `correlationId` 贯穿询盘、报价、订单、发票和回款等长流程。
5. 事件生产者拥有事实，消费者不得反向覆盖生产者记录。
6. 事件字段变化必须版本化并保持旧消费者兼容或提供迁移窗口。
7. 敏感字段不应直接放入公共事件；消费者通过授权接口获取必要详情。

## 事实源边界

- 企业客户和联系人身份归06锁客。
- 询盘和报价归08承转。
- 确认订单、BOM、批次、库存和发运归09强链。
- 商机、客户资产和服务工单归10深养。
- 组织、员工、合同法务、发票和回款归12固本。
- 内容资产归02布场，营销活动归07精投。

报表、搜索索引、缓存、消息队列和AI知识库都不是业务事实源。

## 变更与验收

新增对象或事件必须先通过契约冻结与安全评审，说明生产者、消费者、权限、幂等、版本、补偿、保留和删除。没有至少一个真实黄金业务链消费者时，不应为了“以后可能使用”无限扩张事件。

冻结顺序固定为“22个对象先冻结，14个事件后冻结”。冻结接口会一次校验对象的 `tenantId`、稳定对象ID、事实源及身份规则，并校验事件主题、生产者、消费者、八字段信封和兼容策略。已冻结契约不能原地静默修改；结构变更必须提升 `schema_version`，旧消费者仍需保持向后兼容或明确登记破坏性迁移。
