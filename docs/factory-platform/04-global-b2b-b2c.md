# 国内、海外、B2B、B2C 与 ERP 连接策略

平台采用共享核心领域模型，加上区域策略、交易方案和连接器适配层。区域与交易模式是可组合维度，不通过复制四套平台实现。

## 一、国内 B2B

- 支持企业客户、联系人、分级价格、询价/报价、合同、采购订单和授信审批链路。
- 08.承转形成报价和订单意向，09.强链校验产品、信用/付款条件、库存和产能后认定确认订单，再向 ERP/财务传递获准业务单据。
- 代理场景下，总部控制可售目录与政策，代理负责客户关系、方案和服务过程。
- 验收重点包括企业主体、审批、价格权限、合同版本、订单幂等和财务对账。

边界：平台经营账本不替代法定会计总账；发票、税务和授信规则需按企业制度及专业意见配置。

## 二、国内 B2C

- 支持面向消费者的商品展示、营销活动、购物车/下单、支付、退款和售后状态；结账请求须由09.强链返回确认订单或拒绝结果。
- 用户同意、营销订阅、收货信息和客服记录按最小必要范围保存与使用。
- 库存、价格和履约状态可由 ERP/OMS 提供，前台采用缓存和失效策略保证体验与可追溯性。
- 验收重点包括高并发幂等、库存防超卖策略、支付回调、退款和隐私请求处理。

边界：平台不能保证第三方支付、物流或营销渠道持续可用；促销规则须明确库存、地域、期限和退订限制。

## 三、海外 B2B

- 支持多语言询盘、区域销售归属、多币种报价、贸易条款、样品和批量订单协同。
- 客户、产品和报价展示根据区域策略启用，税费、制裁筛查和出口限制由企业流程及专业服务确认。
- 跨时区任务、审批和服务级别使用统一时间戳，并按用户时区展示。
- 验收重点包括币种精度、汇率来源、区域权限、语言回退、跨境单据和数据驻留要求。

边界：平台提供规则承载和审计能力，不替代出口管制、制裁、税务、隐私或合同法律判断。

## 四、海外 B2C

- 支持区域站点、语言、币种、地址格式、支付方式、配送范围和退货政策的独立配置。
- 商品、价格、库存和营销活动按市场发布，避免某地区内容或优惠误投到另一地区。
- 订单接收、支付状态、履约、退货和客户通知通过区域连接器编排并保留原始回执。
- 验收重点包括结账本地化、支付失败恢复、税费展示、物流状态和数据主体请求流程。

边界：本地化不仅是翻译；未完成支付、税务、消费者权益和隐私评估的市场不得标记为正式可售。

## 五、共享核心与区域扩展

### 共享核心

- 组织、租户、用户、产品、客户、确认订单、发布版本和审计采用统一标识与状态模型。
- 金额统一保存币种和最小货币单位或明确精度，不使用无币种浮点数作为交易事实。
- 时间统一保存 UTC 和来源时区；展示、结算和截止日按业务时区转换。
- 08拥有报价、合同和订单意向；09拥有工程产品、工程标准成本、库存、确认订单和履约；12拥有财务实际成本、正式过账、发票、利润和现金。
- 06拥有客户统一身份、具体触达同意和渠道偏好；12拥有企业隐私政策、合法依据目录、保留制度、角色权限和审计要求。

### 区域扩展

- 语言、币种、地址、税费显示、支付、物流、内容和数据策略通过版本化区域配置启用。
- 区域特有字段放在明确扩展模型或连接器映射中，不污染所有租户的核心字段。
- 每个区域配置都声明责任人、适用模式、验证日期、依赖服务和回退方式。

## 六、ERP 连接原则

1. **先定系统记录源**
   - 产品工程、库存和确认订单登记在09.强链领域，可由现有 PLM/ERP/OMS/WMS 作为物理记录源。
   - 客户统一身份和触达同意登记在06.锁客(画像)领域；CRM只消费统一ID管理关系和行动。
   - 财务实际成本、过账、发票和总账登记在12.固本(经营)领域，以获批财务系统为物理记录源。
   - 工程标准成本与财务实际成本分别版本化和对账，不允许同名字段双向覆盖。
   - 非主系统可提交变更请求或接收副本，但不能无条件双向覆盖。
   - 字段冲突按业务版本、时间和人工审批策略处理，不以“最后写入”默认获胜。
2. **使用防腐适配层**
   - 核心模型只定义业务语义，供应商表名、状态码和字段由适配器转换。
   - 每个适配器声明版本、能力、限流、字段映射和不支持项。
   - ERP 升级先通过契约测试和沙箱验证，再切换生产连接。
3. **事件与批量并存**
   - 高频状态用事件或增量接口，主数据初始化与对账使用可分页批量任务。
   - 每次同步保存来源游标、业务幂等键、映射版本和处理结果。
   - 对方不支持事件时采用增量轮询，并明确数据延迟预期。
4. **失败可恢复**
   - 网络错误、限流和临时失败采用退避重试；永久错误进入可见的人工处理队列。
   - 死信重放保持原业务幂等键，避免重放生成重复订单、库存扣减或账目。
   - 每个连接提供健康状态、最后成功时间、积压量和对账差异。
5. **安全与审计**
   - 凭据集中加密管理、最小权限、定期轮换，禁止写入前端、仓库和普通日志。
   - 数据传输使用受支持的加密协议，敏感字段按目的和区域最小化。
   - 连接、同步、补偿和人工改写均记录租户、操作者、来源和结果。

## 七、建议接入顺序

1. 只读同步产品、客户或库存，完成字段与口径验证。
2. 打通一条低风险写入链路，例如09认定的确认订单进入 ERP 沙箱，并将财务状态回传12。
3. 增加状态回传、失败补偿、对账和监控，再进入有限生产试点。
4. 通过容量、灾备和业务验收后扩大组织、区域或交易类型范围。

## 八、连接验收清单

- 字段映射、主系统、币种精度、时区、状态转换和删除语义均有文档。
- 重复消息、乱序消息、断线、限流、无效数据和部分失败场景均有测试证据。
- 对账能够从平台记录追溯到 ERP 原始标识，差异有负责人和处理状态。
- 停用连接不会删除历史业务数据，并提供未完成任务的导出或迁移方案。
