# 行业包与国家区域包规范

配置包是在统一平台内核上组合字段、规则、流程、模板、连接器与验收证据。它不能复制客户应用、改变核心对象含义，或形成长期分叉代码。程序事实源为 `FACTORY_PLATFORM_INDUSTRY_PACKS` 与 `FACTORY_PLATFORM_COUNTRY_PACKS`。

## 首个可运营行业包

首个行业包锁定为 `industrial-pump-valve`（工业水泵与阀门），不是泛化的“机械行业”。它把营销、询报价、成交和售后资产服务接到同一条对象链上。

| 交付项 | 必填内容 | 验收目的 |
| --- | --- | --- |
| 对象映射 | `product, sku, inquiry, quote, order, customer-asset, service-ticket` | 行业字段不改变七个核心对象的身份 |
| 产品参数 | 流量、扬程、压力、介质、温度、材质、连接、电机、电压、认证 | 支持选型、内容、报价与合规复用 |
| 选型规则 | 工况到产品和 SKU 的匹配与人工复核规则 | 避免销售凭经验漏项或错配 |
| RFQ 模板 | 买方、工况、数量、贸易术语、目的地等字段 | 统一国内外询盘资料质量 |
| 序列号资产 | 订单、产品、安装点、调试、保修的序列号链 | 把一次成交转成长期客户资产 |
| 配件服务 | 资产、工单、配件 BOM、报价、发运、解决状态 | 打通售后复购和客户终身价值 |

发布前必须提供三项证据：行业对象图、真实报价样本、已安装设备服务链样本。还必须先完成同项目的 7/30/90 天客户实施计划。

## 生命周期与版本

行业包安装状态按 `draft → validated → published` 单向推进：

- 草稿可保存配置与证据，所有更新使用 `expected_revision` 防止并发覆盖。
- 验证检查六项配置、三项证据、七个受治理核心对象，以及客户实施完成状态。
- 发布后版本只读。任何修改必须创建更高版本，确保已交付客户可以追溯和回滚。
- 所有创建、更新、验证和发布动作均按租户及项目鉴权并写入审计日志。

接口统一位于：

`/api/v1/factory-platform/projects/{project_id}/industry-packs`

支持列表、创建、更新、验证与发布；当前仅允许 `industrial-pump-valve`，防止未调研的泛行业模板进入生产。

## 国家区域包

- 中国市场：中文、人民币税价、国内支付、电子发票与隐私文本。
- 欧盟市场：多语言、欧元、隐私同意、产品护照、碳关税及目标国规则。
- 北美市场：英语/法语、美元/加元、州省税务、认证与隐私。
- 东盟市场：多语言币种、区域电商、物流、进口资料与本地支付。
- 中东市场：英语/阿语、区域币种、认证标签、代理与本地渠道。

国家区域包只提供初始范围。每次实施仍需根据客户主体、产品、目的国、交易方式和当期官方规则进行专业复核。

## 配置边界

允许配置：字段显示、必填规则、术语、模板、连接器、审批路径、国家法规清单、报表和验收样本。

禁止配置包修改：租户隔离、对象 ID 含义、事件信封、事实源所有权、审计要求、数据导出权、AI 人工复核和高风险操作权限。

## 数据库迁移与回滚

迁移 `e9a2c5f8b316` 只新增行业包安装的配置、证据、版本、状态和审计关联记录。降级会删除这些安装控制记录，不会删除产品、报价、订单、客户资产或服务工单。生产回滚前应先导出已发布配置包快照，应用回退到前一版本后再执行 Alembic downgrade。
