# 02.布场（内容）｜客户网站建设至正式运营全链路规范

## 0. 目标和完成定义

本规范把网站建设定义为一项可运营交付，而非“页面做好即可”。每个客户站从立项到运营，必须完成：

`范围确认 → 站点策略 → 内容与素材准备 → 视觉/页面生产 → 多语言与市场路由 → 连接与转化 → 全量验收 → 灰度上线 → 30/90 天运营复盘`。

只有当客户真实域名（或获准的预发布域名）可访问、目标语言内容完成审核、关键转化动作可用、数据与错误监控生效、客户完成验收且有可验证恢复点时，状态才可从“建设中”变为“正式运营”。

本规范使用既有三端发布分支：`总部 → 客户源 → 客户计划/站点`。不得由总部绕过客户源直接修改客户运行站点。

## 1. 角色与责任

| 角色 | 负责 | 无权做的事 |
| --- | --- | --- |
| 客户业务负责人 | 目标市场、产品优先级、法定内容、上线确认与经营指标 | 不可绕过审批发布或修改平台基线 |
| 客户内容负责人 | 企业资料、产品、案例、语言人工稿、素材授权 | 不可自己审核/发布自己的高风险版本 |
| 客户技术负责人 | 域名账户授权、DNS、邮件、分析、商城/CRM 接口确认 | 不可把密钥写入普通内容配置 |
| 代理/实施顾问 | 方案配置、迁移、培训、问题闭环和交付证据 | 不可替客户确认法律、域名转出或支付动作 |
| 客户源运营者 | 来源模板、差异预演、灰度发布、恢复点 | 不可改写运行站业务数据和锁定覆盖 |
| 平台总部 | 标准、共享组件、版本、连接器契约与重大事件支持 | 不可直发客户站点 |

发起、复核、发布和外部回执遵守职责分离；同一人不能完成自身提交的翻译复核、发布批准或外部配置回执。

## 2. 全链路阶段、输入、产物和放行门槛

| 阶段 | 主要工作 | 必交产物 | 放行条件 |
| --- | --- | --- | --- |
| 0. 立项与范围 | 明确目标市场、B2B/B2C、语言、站点类型、成功指标与边界 | 《站点简报》、RACI、风险清单、实施计划 | 客户确认范围；无未决的域名/法律/事实源阻断 |
| 1. 站点与路由策略 | 选择品牌/营销站，子域或路径策略，国家和语言映射 | 站点空间、信息架构、`MarketRoute` 方案、URL 清单 | canonical/hreflang/重定向方案审阅通过 |
| 2. 事实、内容与素材 | 建企业/产品/证明主档引用，素材权利与术语 | 内容矩阵、素材权利清单、术语库、缺口台账 | 无无来源规格、过期证书或无授权素材进入页面 |
| 3. 页面与视觉生产 | 选择品牌系统、模板、模块及 B2B/B2C CTA | 页面树、断点预览、组件绑定、可视化草稿 | 共享框架、无障碍、移动端和锁定规则通过 |
| 4. 多语言与区域化 | AI 初译、人工修改、区域审核、元数据本地化 | 语言包、译文差异、区域审核结论 | 每个上线语言无缺译、术语漂移和 RTL 失败 |
| 5. 转化与连接 | 表单、CRM/询盘、电话/WhatsApp、商城跳转、分析归因 | 字段映射、同意文案、测试记录、失败补偿方案 | 测试数据可追踪；不把测试写入生产业务记录 |
| 6. 质量与预发布 | 链接、SEO、性能、安全、权限、发布差异及回滚演练 | QA 报告、发布清单、恢复点、UAT 记录 | P0 阻断清零；客户确认候选版本 |
| 7. 灰度和正式上线 | DNS/TLS 检查、按市场/语言发布、实时观察 | 发布记录、外部回执、监控基线 | 关键链路和监控通过稳定窗口 |
| 8. 30/90 天运营 | 内容迭代、SEO/GEO、询盘质量、转化、站点健康 | 30 天复盘、90 天价值报告、优化待办 | 指标可解释；遗留问题有负责人和时限 |

## 3. 阶段 0：立项与范围

每个项目创建 `WebsiteBuildProgram`，绑定 `tenant_id / client_id / plan_id / project_id / agent_path`，并关联实施中心的 7/30/90 天周期。站点简报至少回答：

1. 做国内 B2B、海外 B2B、B2C 还是混合？各自的转化动作是什么？
2. 第一批国家、语言、产品线、行业和渠道是什么？不做什么？
3. 采用品牌官网、行业站、国家站、商品站还是活动页？
4. 成功不以“页面数量”计算，而以有效询盘、样品申请、渠道预约、加购/跳转成交或合格流量等可核验目标定义。
5. 产品、价格、库存、资质、客户案例、隐私/条款、域名和数据分析分别由哪个权威系统或责任人确认？

范围变更必须保存版本；新增国家、语言、域名、交易流程或外部连接器视为新的影响评估，而不是设计师临时改页。

## 4. 阶段 1：站点、语言与路由设计

### 4.1 站点空间

一个 `SiteSpace` 代表可独立发布、监控和回退的网站；它可有多个市场语言变体，但只能有一个主路由策略：

- **子域策略**：如 `hk.example.com`，适合独立地区团队、法务边界或 CDN 要求。
- **路径策略**：如 `example.com/hk`，适合统一品牌和 SEO 资产。

策略选择完成后生成：主域、语言、地区、路径、默认语言、替代语言、canonical、hreflang、sitemap、robots、301/308 映射与失效 URL 清单。不能同时把同一内容的子域和路径版本开放索引。

### 4.2 站点地图

站点地图必须区分：

- 品牌信任层：主页、关于、工厂、能力、资质、服务保障、联系。
- 产品决策层：品类、产品、规格、应用、下载、FAQ、对比。
- 证明增长层：案例、新闻、视频、博客、资源中心、活动页。
- 转化层：询盘、样品、预约、经销合作、购买/商城跳转、感谢页。

任何页面都要有清晰受众、搜索/投放意图、一个主 CTA、内容来源和市场语言归属。没有业务目的的“凑页面”不进入发布包。

## 5. 阶段 2：内容、素材和事实治理

网站内容采用“引用优先”原则：

- 企业资料由 `content.company` 管理；产品事实由 `content.product` / PLM 或授权产品主档提供；案例、新闻、视频由 `content.proof` 管理。
- 价格、库存、订单、交期、资质有效性和支付不在页面中手工制造事实；页面只能展示经过授权的快照或权威系统链接。
- 素材进入页面前必须具备来源、权利范围、适用市场、语言和有效期；DAM 只引用私有存储资产，不复制或删除原始文件。
- 先建立品牌词、产品术语、禁译词和法律术语，再启动翻译；产品型号、证书编号、品牌名、商标和法定名称默认禁译。

内容矩阵每行必须有：页面、区块、来源对象、责任人、目标市场、语言、SEO 关键词/意图、CTA、审核状态、有效期和版本。

## 6. 阶段 3：可视化生产与响应式验收

页面在可视化编辑器中以 `Page → Section → Block → Binding` 构成，所有变化生成版本补丁。

强制检查：

- 手机、平板、桌面三种预览；没有横向滚动、被遮挡 CTA 或不可点表单。
- 品牌型和营销型模板可以切换，但模板仅改可继承令牌与区块，不能覆盖客户锁定内容、法律文本和业务事实。
- 每一个视频、图像、组件、表单和弹窗有性能预算、替代文本、加载失败兜底及可访问名称。
- 共享样式只能通过共享契约写入；页面清扫器和代码删除器不能删除 `02.布场` 的受保护栏目与路由。

## 7. 阶段 4：翻译、区域化与 SEO

翻译状态固定为：`source-frozen → machine-draft → human-edited → regional-review → approved → published`。

- 后台可按页面/区块切换语言，显示源文、机器建议、人工稿、术语命中、差异与发布版本。
- 必须本地化：正文、标题、描述、结构化数据、图片 alt、表单提示、邮件、URL slug、货币/单位/日期、电话、地址和 CTA。
- 翻译者不可复核自己文本；机器翻译不能发布；任何语言缺失、术语错误、市场合规缺口或渲染失败都会阻断对应语言发布。
- 每个市场验证 `canonical`、`hreflang`、可索引性、站点地图、robots、404、重定向和语言切换回跳。

## 8. 阶段 5：转化、连接和数据边界

### 8.1 B2B 转化

询盘、样品、报价、技术资料下载、预约和经销申请必须携带来源页、市场、语言、活动标识、同意版本和幂等键，并受 `inquiry-routing` 与 CRM 权威流程接收。站点仅创建受控线索意向，不自行把线索改成报价、订单或客户。

### 8.2 B2C 转化

加购、结算、支付和库存只能由商城/commerce/OMS 权威系统处理。内容站可以安全跳转或消费只读商品快照；不得把静态页面价格视为结算价格，或在编辑器中写入支付密钥。

### 8.3 分析与同意

分析事件需覆盖曝光、CTA、表单启动/提交/失败、下载、外跳、语言切换和购买意向；所有个人标识和营销用途遵守同意规则。测试事件必须有 `environment=test` 标记，不进入生产归因或 CRM 路由。

## 9. 阶段 6：上线前 Go/No-Go 清单

以下任一 P0 未完成即 `NO-GO`：

| 检查项 | 通过标准 |
| --- | --- |
| 域名与 TLS | 主域/子域解析、TLS、HSTS 策略和 DNS 记录经责任人确认 |
| 路由与 SEO | canonical、hreflang、robots、sitemap、301/308、404 与语言跳转通过 |
| 内容事实 | 规格、资质、案例、法律文本、联系信息有来源且在有效期内 |
| 多语言 | 上线语言均通过人工/区域复核；无缺译、禁译词和布局错误 |
| 响应式与无障碍 | 手机/平板/桌面关键流程可用，无阻断级可访问性问题 |
| 转化 | B2B 表单到达受控路由；B2C 跳转/商品快照正确；失败路径可见 |
| 安全与权限 | 无前端密钥、调试入口或跨租户内容；编辑/发布权限与审计完整 |
| 性能与可观测性 | 核心页面性能预算、错误监控、可用性探测、发布后仪表盘就绪 |
| 恢复 | 已创建版本恢复点，完成预演，明确 DNS/内容/模板/连接各自回退步骤 |
| 客户验收 | 客户业务、内容和技术三方按职责签署 UAT；遗留项有风险级别和期限 |

## 10. 阶段 7：发布、观察与回滚

发布顺序固定：

`客户源版本冻结 → 差异预演 → QA/UAT → 恢复点 → 预发布/灰度 → 生产发布 → 外部回执 → 稳定窗口 → 关闭变更`。

- 先发布一个市场/语言或预发布域名，观察错误、表单、分析和外部跳转；不以“网页能打开”替代转化验收。
- 回滚按范围执行：页面/语言包/品牌令牌/站点版本可独立回退；域名、DNS、商城、CRM 和支付按外部系统自己的回滚契约处理。
- 回滚不删除客户后来新增的内容、素材、线索、订单、分析事件或外部记录。
- 生产发布完成后，需在 30 分钟、24 小时、7 天三个窗口检查可用性、索引、错误、表单送达和转化趋势。

## 11. 阶段 8：30/90 天运营闭环

### 30 天：稳定与第一轮优化

- 检查自然流量、投放落地、语言流量、表单送达、无效询盘、页面速度和错误。
- 按数据优化 CTA、证明内容、FAQ、表单字段和目标页面，不改写产品/价格/库存权威事实。
- 输出《30 天网站健康与转化报告》：发现、证据、动作、负责人、完成时间和下轮假设。

### 90 天：价值与扩展决策

- 对比目标市场、语言、内容类型、渠道和受众的询盘质量、商机、成交辅助、B2C 跳转/成交回执。
- 决定是否扩展国家/语言、行业页、营销页、商城连接、注册商能力或 AI 沙盘授权范围。
- 输出《90 天价值报告》和下一阶段投资优先级；不能用没有归因证据的浏览量承诺收入。

## 12. 工程实现门禁

每个建设链路能力必须补齐真实数据模型、项目权限、审计、API、前端页面、对象/事件契约、迁移和回滚说明、自动化测试、TypeScript、生产构建与真实页面验收。

首批开发次序：

1. `WebsiteBuildProgram`、站点简报、阶段门禁和证据台账。
2. `SiteSpace / MarketRoute / PageCompositionVersion / LocalizedPageVariant` 与可视化编辑、预览、版本差异。
3. 翻译人工改稿、术语和区域审核；路由/SEO 发布校验。
4. B2B 表单路由、B2C 权威商城跳转、分析同意与监控。
5. 灰度、UAT、回滚演练和 30/90 天报告。
6. 最后才逐个启用注册商、CDN、支付和其他外部有状态连接器。

## 13. 对客户的交付包

每个正式运营客户至少获得：

- 已批准的站点简报、信息架构、市场/语言/路由清单和页面清单。
- 内容矩阵、术语库、素材/权利清单、品牌系统和可视化页面版本。
- UAT、发布、域名/DNS、监控、分析与回滚证据。
- 编辑权限说明、语言人工修改指南、域名转出/数据导出说明、30/90 天运营报告模板。

这样客户购买的是一套可持续经营、可迁移、可审计的网站资产，而不是一次性网页交付。
