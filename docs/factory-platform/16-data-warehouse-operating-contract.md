# 经营数据仓库运营契约

## 业务定位

经营数据仓库不是第二套 ERP，也不允许直接修改报价、订单、质量、资产、回款或客户之声。它只读复制已经由权威业务系统确认的事实，为健康驾舱、指标中心、预测分析和经营决策提供同一套可追溯数据底座。

客户购买的核心价值不是“多一个报表”，而是让跨部门争议从“谁的 Excel 正确”变成“这条指标来自哪个业务对象、哪个修订版本、哪次装载和谁批准发布”。

## 受控来源

首期仅允许平台内部批准的适配器：报价、订单、质量、客户资产、回款和伙伴/客户之声。登记时保存业务目的、数据所有者、保留周期和租户边界；启用前必须提交模式契约与审批证据。接口不会接收任意 SQL、数据库地址或凭证，也不会向前端暴露连接凭证。

每个来源遵守以下状态：

`draft → active`

- `draft`：数据所有者完成用途和责任登记，尚不能抽取。
- `active`：审批人确认模式契约和指纹，可以按水位只读装载。

## 不可变事实与装载血缘

事实版本唯一键为 `tenant_id + source_code + source_object_id + source_revision`。同一业务对象修订未变化时再次装载，只复用已有事实版本；但每个装载批次都新建血缘边，证明该批次实际包含哪些事实。任何分析记录都必须保留：

- 权威来源系统与表；
- 来源对象 ID、业务编号和修订号；
- 来源更新时间、观察时间和内容哈希；
- 首次装载批次、当前批次血缘和转换规则；
- `agent_path`、`tenant_id`、`client_id` 与 `plan_id`。

## 质量门禁与独立发布

装载批次按以下状态运行：

`extracted → validated → published`

如果快照为空、权威必填字段缺失、修订号无效或行数不守恒，则进入 `failed`，不能发布。发布人不得与校验人相同；发布成功后才更新来源的最后发布批次和水位。所有登记、启用、抽取、校验、失败与发布动作同时写入业务证据和平台审计日志。

## 权限与三端边界

- 总部端：可定义公司级数据来源、治理规则与发布职责。
- 代理端：仅处理获授权客户计划，可承担独立审批或发布。
- 客户端：在自己的项目与计划内登记、抽取、校验和查看，不得越租户访问。

权限拆分为来源管理、来源审批、装载执行、质量校验和独立发布五项，不使用一个“数据管理员”权限绕过职责分离。

## 运营验收

上线前必须证明：来源已审批启用；一次非空装载的读取数等于接受数加拒绝数；每个接受事实都有该批次血缘；阻断问题不可发布；校验人与发布人不同；发布水位可从页面、API、证据和审计日志四处相互核对；生产构建和真实浏览器流程均通过。
