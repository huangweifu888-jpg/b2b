# 合同法务运营契约

## 业务定位

合同法务是工厂跨境 B2B/B2C 交易的法律记录系统，不是附件列表，也不复制报价、采购或审批中心。报价与采购继续保管商业事实，审批中心保管跨域批准；合同法务只在收到同一项目、同一来源、同一修订号的已确认审批交接后，建立法律主体、合同文本、用印、签署和履约义务记录。

完整状态链为：`法律主体草稿 → 独立启用`、`模板草稿 → 不可变版本独立启用`、`合同草稿 → 提交法审 → 独立批准 → 受控用印 → 第三方签完 → 合同生效 → 义务完成/独立豁免`。最终签署不会修改 CPQ 报价或采购订单。

## 法律主体与数据最小化

客户主体来自 CPQ 报价的客户引用，供应商主体来自已批准供应商档案；采购合同按采购单的 `supplier_id` 精确匹配供应商主体。主体需有注册资料引用、税务资料引用、注册地址引用、KYB 证据和制裁筛查证据。

原始登记身份键只用于生成租户内 SHA-256 身份指纹，生成后立即丢弃，不写数据库、不写审计详情。相同租户中的相同身份指纹必须拒绝，跨租户不能互查或去重。主体作者不能启用自己创建的主体。

## 不可变模板与合同版本固定

模板至少包含三条有实质内容的受控条款，并固定语言、适用法律、争议解决方式、受控文档引用和内容哈希。启用后的模板版本没有修改接口；变化必须形成新版本和新审批，已经被合同引用的内容哈希不能静默改变。

合同创建时同时固定：法律主体及其修订号、模板版本及内容哈希、商业来源类型/编号/修订号/快照、审批中心交接编号、币种、金额、有效期、到期日、续期设置、通知天数和受控草稿引用。提交法审前再次核验全部固定点；任一来源或主体发生变化都必须重建草稿。

合同作者或提交人不能执行法律审查。法审必须记录低/中/高/重大风险、每项条款偏差及解决方案、批准或驳回建议、意见和证据。批准只改变合同法务自身状态，不回写商业来源。

## 用印与第三方签署

用印只针对已完成独立法审的合同和一个明确的 SHA-256 文档哈希。申请人与批准人必须分离；授权只能核销一次。数据库保存用印类型、目的、批准和使用证据，不保存可复用电子印章材料。

电子签署通过供应商适配层保存供应商引用、外部信封引用、签署人引用、事件引用和证据引用。不得保存签署私钥、原始签章图片或供应商密钥。信封要求 2 至 10 个唯一签署人；全部签署人的供应商事件均被登记后，信封才完成，合同才进入 `active`。

## 履约义务

只有生效合同可建立交付、付款、验收、合规、通知、续期或报告义务。义务必须位于合同有效期内，并固定责任人和到期日。只有责任人可凭证据完成义务；责任人不能豁免自己的义务，豁免必须由独立人员并附证据完成。履约率按已完成和已独立豁免的义务计算，逾期和 90 天内到期合同独立监控。

## 权限、租户与审计

权限拆分为主体管理/启用、模板管理/启用、合同管理/法审、用印管理/批准、签署管理和义务管理十项。每条记录携带 `project_id`、`agent_path`、`tenant_id`、`client_id` 和 `plan_id`；读写均以项目授权过滤。所有状态动作同时追加法务证据和带项目 ID 的平台审计，修订号阻止陈旧页面覆盖新状态。

总部维护统一合规底线和供应商适配规范；代理人员只能在获得项目权限后承担指定法审或批准职责；客户对主体资料、合同决定、用印授权、签署关系和履约结果承担最终责任。

## 上线验收

必须证明：原始登记身份键不落库；租户内重复主体被拒绝；主体和模板不能自批；模板版本不可修改；合同必须使用已确认审批交接并固定来源修订；来源漂移会阻止提交；作者不能自审；用印不能自批且只能使用一次；数据库没有私钥或印章图像；全部第三方签署事件到齐后合同才生效；履约完成必须是责任人并附证据；责任人不能自豁免；商业来源始终不被合同法务改写；租户隔离、权限、审计、迁移回滚、自动测试、生产构建、三身份 API 和真实页面闭环全部通过。
