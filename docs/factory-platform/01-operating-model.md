# 12 类运作逻辑与业务边界

本文件以 `frontend/src/lib/factory-platform-blueprint.ts` 为唯一产品事实源。十二类顺序、类别名称和每类六个应用均与程序契约一致，共 72 个应用；文档不得另建同名但不同含义的分类。类别编号用于产品目录，实际经营闭环和开发阶段另见本文末尾与路线图。

“唯一事实源”指该业务事实的最终认定位置。外部 ERP、PLM、MES、WMS、CRM 或财务系统可以是物理记录源，平台中的对应类别负责登记其所有权、适配和消费规则，不因最后一次接口写入而改变事实归属。

## 01.蓄势(身份)

蓄势负责产品机会、市场定位、客户定位、品牌身份和数字资产准备。

| 应用（程序 ID） | 目标 | 唯一事实源 | 明确边界 |
| --- | --- | --- | --- |
| 产品分析（`identity.product-intelligence`） | 识别有利润和增长空间的产品机会 | 产品机会研究库 | 研究结论须标来源和时间；不改写PLM工程事实 |
| 全球市场机会雷达（`identity.market-radar`） | 评估国家、行业、渠道和进入优先级 | 市场机会版本 | 市场评分不是合规批准或收入承诺 |
| 竞品价格情报（`identity.competitive-pricing`） | 比较竞品、价格带、卖点和渠道动作 | 竞品观察数据集 | 情报价格不直接成为正式报价或财务价格 |
| ICP客户定位（`identity.icp`） | 定义企业ICP、购买委员会和消费场景 | ICP与场景版本 | 战略画像不等于06中的真实客户身份或个人同意 |
| 品牌定位与网站风格（`identity.brand`） | 统一价值主张、品牌、VI、语气和网站风格 | 品牌规范版本 | 不发布页面、不覆盖客户受保护品牌配置 |
| AI计划与数字资产（`identity.digital-assets`） | 管理AI建站计划、域名和品牌数字资产 | 数字资产登记簿 | AI建议需人工批准；域名、商标和授权状态必须可追溯 |

### AI计划与数字资产商业闭环（实施约束）

数字资产应用将以“计划草稿 → AI建议 → 人工审核 → 域名/商标/授权登记 → 独立批准 → 受控交接”运行。它只保存资产引用、权属状态、审批证据与版本指纹，不保存注册商密钥，不自动购买、绑定、转移域名，也不自动发布或覆盖站点、模板和客户保护配置。每个对象必须具备 `project_id + agent_path + tenant_id + client_id + plan_id`，并以独立审核、审计事件与回滚清单保护三端共享契约。

| AI问数与战情中心（`decision.ai-command`） | 用授权数据问数、模拟并生成责任任务 | AI请求、事实引用、审批和任务记录 | AI建议不得直接改变主事实，必须可追溯且有人负责 |

## 12.固本(经营)

固本负责企业经营治理、财务过账、组织人事、审批和法务主数据。它消费 09.强链确认的订单及工程成本，不拥有订单确认、库存或生产事实。

| 应用（程序 ID） | 目标 | 唯一事实源 | 明确边界 |
| --- | --- | --- | --- |
| ERP经营总台（`operations.erp`） | 统一公司、工厂、项目和成本中心的经营底账 | 经登记的 ERP/经营主数据 | 只引用 09.强链的确认订单；不得另建订单确认状态或覆盖履约事实 |
| 财务资金中心（`operations.finance`） | 管理应收应付、预算、收付款、多币种和现金流 | 财务总账及获批子账 | 拥有财务实际成本、正式过账、发票和现金；不改写工程标准成本 |
| HR人事中心（`operations.people`） | 连接组织、员工、合同、绩效、培训和人效 | HR 人事主档 | 不将营销联系人或客户画像写入员工主档 |

| 合同法务与主数据（`operations.legal-master-data`） | 维护合同模板、证照、政策、编码和治理责任 | 合同/证照库与主数据治理目录 | 经营政策和隐私制度归此管理；个人触达同意归 06.锁客(画像) |

## 跨类唯一事实源

- **产品数据分层**：01拥有市场定位和价值表达；02拥有渠道文案、媒体和翻译；09拥有工程规格、SKU、BOM、工艺版本、工程标准成本和库存；04只发布机器可读副本；12只拥有财务实际成本与正式过账。
- **订单边界**：08拥有询盘、RFQ、样品、报价、合同和订单意向；09校验产品、信用/付款条件、库存和产能后认定确认订单，并拥有后续履约状态；12消费确认订单做应收、发票、实际成本、利润和现金过账。
- **成本边界**：09的工程标准成本用于设计、报价参考和制造控制；12的财务实际成本来自获批领料、工时、采购、费用及会计规则。两者必须带版本和口径，不互相覆盖。
- **同意与政策边界**：06拥有具体个人或企业联系人的营销触达同意、退订和渠道偏好；12拥有企业隐私政策、合法依据目录、保留制度、角色权限和审计要求。
- **客户边界**：06拥有统一客户身份、事件、标签和分群；10消费统一ID管理关系、服务、续约和增购；11只计算客户利润、LTV和风险。
- **决策边界**：11汇聚、计算、预测和建议，但任何正式业务变化仍由12、09、08、06或10的责任系统执行。

## 全生命周期闭环

闭环主路径为：`01身份蓄势 → 02内容布场 → 03搜索信任 → 04AI/平台推荐 → 05社交深耕 → 06画像分群与同意 → 07付费触达 → 08询盘报价与订单意向 → 09确认订单与履约 → 10客户成功与复购 → 11经营决策 → 12经营固本 → 01下一轮身份蓄势`。

06.锁客(画像)不是一次性的线性终点，而是**横向画像**与事件层：在社交信号后、付费投放前提供授权分群，同时持续接收07投放、08成交、09履约和10服务事件。09也持续向01、02和08提供获批产品、库存、标准成本与交付能力副本。
