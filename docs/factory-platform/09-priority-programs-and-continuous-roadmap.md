# 五个优先专项与持续开发七步路线

专项跨越多个业务类别，目的是打通端到端结果，不新建重复应用。程序事实源为 `FACTORY_PLATFORM_PRIORITY_PROGRAMS` 与 `FACTORY_PLATFORM_CONTINUOUS_DEVELOPMENT_SEQUENCE`。

## 五个优先专项

### 1. 智能报价

连接产品身份、CPQ、履约和财务，覆盖产品选型、阶梯价格、MOQ、汇率、运费、毛利、审批、合同和报价转订单。首要验收是报价行关联权威产品版本、价格有效期和审批证据。

### 2. 产品护照

连接产品身份、BOM、材料、供应商、批次、证照、维修和回收信息。护照数据必须可追到权威来源、按角色控制访问并保留版本和审计。

首个可运营版本由 `fulfillment.plm` 的 `/product-passports` 独立应用承载：工程版本先建立规格和至少两项带供应商、数量、单位、原产国的BOM，再经发布审批冻结；产品护照必须引用同租户计划内已交付订单的工单、生产批次、质量放行、发运和签收证据，核验至少一份当前有效证书后才能发布 SHA-256 追溯摘要及二维码载荷。已安装客户资产只通过订单、产品和SKU稳定ID反查，不复制到PLM主档。

产品护照的法规和行业字段必须在实施时重新核对客户产品、目标市场及最新官方规则，平台规范不替代法律或认证意见。

### 3. 价值证明

建立上线前基线、实施范围、统计周期、指标口径和客户授权，形成续费、增购和销售证据。结果必须可以下钻到权威业务事实。

### 4. 碳贸合规

按产品和批次汇集原料、能源、运输、排放因子和贸易资料。排放因子、计算规则和申报输出必须带来源、版本并经过合规负责人审批。

### 5. 客户资产

登记客户已购买设备、项目、序列号、保修、配件、耗材、维护和续费关系。客户资产关联确认订单，但不得覆盖产品主档、订单或财务事实。

## 持续开发七步顺序

1. **打通底座**：统一对象ID、事件、租户权限、流程、审计和价值基线。
2. **打通成交**：完成产品选型、智能报价、审批、合同、订单意向和收付款状态。
3. **打通履约**：完成供应、质量、批次、库存、发运、签收和售后资产。
4. **打通合规**：完成产品护照、证照、产品碳账和申报证据。
5. **打通深养**：完成客户资产、服务维护、续费增购和价值证明。
6. **打通智能**：完成授权知识、模型评测、人工复核、预测和责任任务闭环。
7. **开放生态**：形成连接器市场、开发者契约、行业方案包和伙伴认证机制。

## 当前开发优先原则

- 第一优先不是增加页面，而是冻结统一对象、事件、权限和事实源。
- 第二优先是智能报价，因为它连接营销承诺、订单、制造能力和利润。
- 第三优先是产品追溯与客户资产，让交付和长期价值进入同一链路。
- 合规和AI能力必须建立在可追溯事实上，不得先做不可审计的自动化外观。
- 每完成一步，都要通过对应门禁并完成价值复盘，再进入下一步或扩大范围。

## 专项停止条件

如果专项无法明确事实源、责任人、客户价值、失败补偿、合规边界或验收指标，应停止开发并返回立项评审；不得通过新增菜单、原型页面或AI文案制造“已经开发”的假象。

## 当前履约权威顺序

订单确认、工单与生产批次完成后，必须先由 QMS 完成五项检验、NCR/CAPA 闭环和批准放行，再由 OMS 接受同一质量证据进入发运；产品护照只能引用该冻结的质量放行事实。这个顺序保证“生产完成”不被误当成“质量合格”，也使客户验厂、客诉追因、证书审查和产品追溯共享一条证据链。

供应采购位于工程发布与生产计划之间：SRM 只能从已发布 BOM 和确认订单计算采购数量；供应商准入、采购审批、正式下单、供应商承诺和真实收货必须保留为五类不同证据。供应商说“已发货”或承诺某日到货，不能替代仓库收货、来料质量或财务应付事实。

产销计划承接确认订单、工程 BOM 和采购收货，只在已审批的有限产能资源上计算工作日排程。MRP 缺料和 APS 延期是可评审风险，不是可被人工备注绕过的提醒；任一风险未清零时不得释放工作单意向。任何到料或产能变化都要求重算并重新审批，MES 只能接收最新释放的计划意向。

MES 把最新计划意向转为唯一制造工单，并冻结领料批次与工艺路线。工序必须顺序报工，良品与报废守恒，停机必须先恢复并留证；MES 完工只证明制造谱系结束，仍不能替代 QMS 质量放行、仓库入库或财务实际成本过账。

现场服务位于客户资产之后：资产服务工单仍是问题与 SLA 的权威身份，现场服务应用只增加工程师技能授权、派工、出发、到场、诊断、工时、备件领用凭证和客户签收。备件记录只能引用库存出库凭证，不能直接修改库存或形成财务过账；客户签收完成后再由资产服务工单产生冻结的 `service-resolved` 事件，避免两个工单主档相互冲突。

质保退货必须从同一资产的已解决服务工单启动，随后把客户申请、质保资格、退回授权、承运凭证、仓库收货、RMA 检验、QMS 结论、责任处置、预计质量成本、维修或换退结果以及客户确认拆成独立证据。RMA 的仓库凭证不能替代库存入库，预计成本不能替代财务冲销，制造缺陷不能在缺少 QMS 证据时直接赔付或拒赔。

续约增长只能从已进入到期行动的有效客户资产建立机会，并冻结订单、产品、序列号、保修、服务次数、已解决工单和制造责任 RMA 快照。健康分只是透明规则形成的行动信号，不能替代客户确认。增购建议必须同时具备价值证据、客户需求确认、产品与 SKU、数量、价格成本和毛利，再经独立批准进入 CPQ；续约应用不得复制原订单或自行制造成交。

成交权威顺序固定为 `机会评估 → 建议与客户确认 → 增长审批 → CPQ移交 → 报价接受 → OMS订单确认 → 续约成交`。续约应用只引用 CPQ 已接受报价和 OMS 已确认订单；报价必须匹配同一客户及批准的产品、SKU和数量，原装机订单禁止循环复用。预计价值不能替代报价金额，报价金额不能替代正式订单或财务回款。
