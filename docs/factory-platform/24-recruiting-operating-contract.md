# 招聘面试中心运营契约

## 业务定位

招聘面试中心是岗位需求、候选人授权、应聘、结构化面试、人工录用决定、Offer与入职交接的业务权威。岗位编制来自HR人事中心；录用后只生成待消费的人事交接，不直接制造员工、合同、工资或财务记录。

候选人必须来自本人投递、员工推荐或受控招聘机构，并提供同意、隐私告知、资料保留期限及外部档案引用。营销联系人、CRM线索、广告受众和抓取简历不得导入。平台不保存简历正文，只保存受控档案引用。

## 岗位需求与候选人

招聘需求状态为 `draft → open → closed`，必须连接有效HR岗位，现有在岗人数与全部开放需求之和不得超过规划编制。作者不能批准自己的招聘需求；需求固定岗位、人数、用工类型、地点、到岗日期和至少四维结构化评分标准。

候选人同意必须在有效保留期内。到期、撤回或删除请求进入隐私生命周期，不得继续面试、留存或用于人才营销。

## 结构化面试与AI边界

应聘流程为 `applied → interview → offer / closed`。面试只允许人工结构化或AI辅助结构化两种模式，必须固定评分标准版本，记录访谈引用、至少两条回答证据、技能、证据、沟通、诚信四维分数和评语。

AI可以转写、摘要、按既定量表提示证据，但 `ai_autonomous_decision = false` 永远成立。AI模型与版本必须可追踪，不能根据年龄、性别、民族、健康、家庭、政治或其他受保护属性评分。面试评估人不能兼任最终录用决定人，最终推进或淘汰必须由人类复核并写明理由和证据。

## Offer与HR交接

Offer状态为 `draft → approved → sent → accepted / declined`。Offer只保存薪酬等级和受控文件引用，不保存工资发放或银行卡数据；作者不能批准自己的Offer。只有候选人接受的Offer才能生成 `ready` 入职交接。

HR人事中心建立 `source_type = recruiting-offer` 的员工主档时，必须引用真实的 `ready` 交接；员工独立激活后交接变为 `consumed` 并固定员工ID，禁止重复消费或伪造来源。

## 权限、审计与三端边界

权限拆分为需求管理/审批、候选人管理、应聘管理、面试管理/评估、人工决定、Offer管理/审批、交接管理十项。所有记录携带 `agent_path`、`tenant_id`、`client_id`、`project_id`、`plan_id`，状态动作同时写业务证据与带项目ID的平台审计，修订号阻止陈旧写入。

- 总部端：维护候选人隐私、受保护属性、结构化量表、AI辅助和职责分离底线。
- 代理端：只能在获授权计划实施招聘配置或担任被授权复核人，不能跨租户访问候选人。
- 客户端：对岗位需求、候选人合法来源、面试证据、人工决定和Offer承担最终责任。

回滚只删除招聘中心拥有的记录和权限，不删除HR员工、劳动合同、工资、CRM联系人或营销数据。生产回滚前必须导出所有进行中应聘、面试证据、已发送Offer和已接受但未消费的交接。

## 上线验收

必须证明：不能超编招聘；需求和Offer不能自批；候选人同意与保留期有效；营销线索不能导入；面试使用固定量表、访谈和引用；AI不作自主决定；面试评估人与人工终审人分离；只有接受Offer才能交接HR且只能消费一次；租户隔离、权限、修订、证据、带项目ID审计、迁移回滚、生产构建、双角色API和真实页面闭环全部通过。
