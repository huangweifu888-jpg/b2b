# ERP经营总台运营契约

## 业务定位

ERP经营总台统一客户租户内的经营组织、工厂、成本中心、订单项目、经营记账和期间月结。首期底账分类固定为 `management-operating-ledger`，服务订单项目经营分析和内部责任核算，不是正式财务总账、税务账或法定会计凭证。正式应收、应付、预算、收付款和资金预测由“财务资金中心”负责。

ERP不得另建订单确认状态。订单项目只能引用09.强链中OMS已确认且未撤销的订单，固定订单ID、订单号、订单修订号、客户、币种和订单金额；登记动作不得修改OMS订单、确认人、确认时间、履约状态或修订号。

## 经营主数据

经营组织状态为：

`draft → active`

经营组织包含稳定代码、名称、组织类型、本位币和负责人，作者不能审批自己的组织。成本中心只能建立在已启用经营组织下，稳定代码在租户内唯一，类型限定为销售、生产、采购、质量、服务或行政。组织、成本中心和平台租户组织是不同层次：平台组织负责权限边界，ERP经营组织负责客户自己的公司/工厂核算结构。

## OMS订单项目

订单项目只接受 `confirmed / allocated / picked / packed / shipped / delivered` OMS订单，并要求真实确认时间。每张OMS订单在同一租户只能登记一个ERP订单项目；项目币种必须与经营组织本位币一致。登记后的订单修订号用于证明当时引用的权威版本，OMS后续履约变化不会被ERP静默覆盖或反向写回。

## 经营记账与纠错

经营记账状态为：

`draft → pending-approval → posted`

每条记账固定期间、订单项目、成本中心、日期、类别、方向、币种、金额、说明和源证据。类别包括订单收入、材料、人工、物流、服务、制造费用和调整；方向限定流入或流出。作者不得审批自己的记账，只有开放期间中的待审批记录才能过账。

`posted` 记录不可修改和删除。纠错必须在开放期间创建新的反向或调整记录并引用原已过账记录；纠错必须保留同一订单项目和币种。系统不静默重算历史，不把经营记账回写成OMS订单、采购单或正式财务凭证。

## 期间月结

期间以 `YYYY-MM` 标识，状态为：

`open → closing → closed`

期间只能建立在已启用经营组织下，同一组织同一月份只能存在一次。提交月结前必须至少有一条已过账记录，且该期间不能包含任何草稿或待审批记录。提交月结会按订单项目和成本中心生成不可变余额，精确核对流入、流出、净额和过账数量。

提交月结的人不能独立关账。`closed` 后禁止补录、修改、重新汇总或重开；更正只能进入后续开放期间。余额属于管理经营结果，不得宣传为法定利润或正式财务报表。

## 权限、审计与三端边界

权限拆分为经营主数据管理、主数据审批、订单项目登记、记账管理、记账审批、期间管理和独立关账七项。所有变更动作写平台审计并携带 `project_id`；所有业务记录携带 `agent_path`、`tenant_id`、`client_id`、`project_id` 和 `plan_id`。

- 总部端维护ERP业务契约、权限模板、行业主数据模板和连接器规范，不直接经营客户账簿。
- 代理端只能在客户明确授权的项目中实施主数据、对账或独立审批，不能跨客户查看订单和经营余额。
- 客户端拥有自己的组织、成本中心、订单项目、经营记账、月结余额和证据；共享发布不得覆盖这些运行数据。

## 上线验收

上线前必须证明：未确认订单无法登记；已登记项目固定OMS修订且不回写；组织与记账均禁止自审；期间外日期、跨组织组合和非本位币被拒绝；草稿或待审批记录阻断月结；月结提交人与关账人分离；关账余额与全部已过账记录精确对账；关账后禁止补录；已过账记录不可改且纠错采用后续记录；租户隔离、修订冲突、权限、证据和带项目ID审计成立；迁移升级、降级、再升级、生产构建和真实页面闭环通过。
