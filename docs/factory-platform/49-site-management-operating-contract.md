# 02.布场｜多站管理运营契约

## 商业闭环

`站点空间 → 内容版本 → 独立审核 → 发布交接 → 独立批准 → 下游回执`。

每条记录都绑定 `agent_path、tenant_id、client_id、plan_id、project_id`，因此不同客户、计划或项目之间不能相互读取、审核或交接。

## 共享路由迁移

2026-08-06 将 `content.cms` 从历史首页投影 `/` 显式迁移到
`/site-management`。`/` 保留为客户首页；“多站管理”栏目没有删除、改名或并入其它应用。栏目配置、平台蓝图、运营市场、左侧导航和页面锁定器继续只读取共享蓝图契约。

## 强制边界

- 域名只保存权属/引用号，不保存注册商密钥，不购买、绑定或转移域名。
- 内容版本以规范化清单哈希冻结；作者不能审核自己的版本。
- 发布准备者不能批准；批准者不能登记自己的下游回执。
- 本系统不直接发布、覆盖或删除客户网站。它只向独立消费系统交接批准的版本；下游回执是“应用可用”而非“网站已被本系统修改”的证据。
- 回滚只删除本应用的治理投影、权限和对象/事件契约，绝不改写外部站点。

## 可运营证据门槛

必须同时具备：受控数据模型、项目权限与审计、冻结 `site-content-version` 对象契约、冻结 `site-version-released` 事件契约、独立角色链、真实接口/页面、迁移升级/回滚验证、自动测试、生产构建和实际页面验收。门槛未全部通过前，蓝图状态保持 `pilot`；2026-08-06 全部门槛通过后，`content.cms` 已明确提升为 `available`。

三身份真实接口验收命令为 `tools/run_site_management_api_acceptance.ps1`；它以总部建立内容、代理审核/批准、客户侧登记消费回执，输出站点、版本、发布、回执、可用性及非自动化边界证据。2026-08-06 的真实页面验收在 `http://127.0.0.1:3003/zb/client-source/site-management` 得到 live 状态、四条记录、六个生命周期动作且无横向溢出，和接口证据共同构成正式可用结论。

本地页面验收可使用临时 API 端口配合 `VITE_API_PROXY_TARGET`，默认仍为 `127.0.0.1:8000`；该配置仅改变开发代理目标，不会覆盖客户项目的运行时 API 设置。

2026-08-06 真实 API 演练已通过：HQ、agency、client 三个独立本地身份完成起草、审核/批准与回执，发布为 `available`，产生 6 条证据；页面 live 验收仍只认用户实际开发服务重新加载后的结果。
