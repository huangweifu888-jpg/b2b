# 指标语义中心运营契约

## 业务定位

指标语义中心不是报表制作器，也不是允许用户输入任意 SQL 的查询工具。它把“订单金额、交付及时率、客户终身价值”等经营概念固化为稳定指标身份，将每一次口径变更保存为不可变版本，再对经营数据仓库已经校验、发布并具备完整血缘的事实执行声明式计算。

客户购买的核心价值，是让经营会议中的争议从“谁的 Excel 正确”转为可核对的五个问题：指标是谁定义的、使用哪个口径版本、读取哪个仓库批次、由谁计算、由谁独立复核。这样财务、销售、运营和管理层看到的是同一项可追溯经营事实。

## 稳定身份与不可变版本

指标定义使用租户内唯一的 `metric_code` 作为稳定身份。名称、说明、公式、维度、过滤条件、来源和生效时间均属于版本，不允许直接覆盖已经发布的版本。

口径版本状态为：

`draft → pending-approval → published → superseded`

- `draft`：作者可完善声明式公式和变更原因。
- `pending-approval`：内容冻结，等待作者以外的审批人核对。
- `published`：成为该指标的当前可计算口径。
- `superseded`：新版本发布后保留为历史口径，关联的历史结果继续锁定在原版本。

新口径不得追溯到过去生效并静默改写历史。需要历史对比时必须显式建立新的计算批次或迁移项目，保留变更原因、批准人和结果差异。

## 声明式公式边界

首期只允许 `count`、`sum`、`average`、`ratio` 和 `percentage` 五类声明式聚合，字段必须来自已启用且已批准模式的仓库来源。维度最多两个，过滤只允许 `eq` 或 `ne`。接口不接受任意 SQL、脚本、数据库地址或连接凭证。

公式发布时固化来源 ID、模式指纹和公式哈希。仓库来源模式变化时，旧版本不能自动跟随；必须建立新口径版本重新审批。

## 仓库事实与血缘绑定

计算只允许读取同一租户、同一项目、同一来源的已发布仓库装载批次，并要求：

- 仓库批次非空且质量门禁已经通过；
- 来源模式指纹与指标版本一致；
- 每条参与计算的事实都存在该批次血缘；
- 结果保存仓库批次号、水位、事实数、血缘数、公式哈希和口径版本号；
- 维度结果保存为不可变观察值，不反写仓库或业务系统。

指标计算状态为：

`evaluated → published`

计算人不得担任该结果的验证人。只有独立验证通过后，结果才能作为可运营的发布指标被健康驾舱、归因分析、预测或 AI 决策消费。

## 权限、审计与三端职责

权限拆分为四项：指标定义管理、口径版本审批、指标计算执行、计算结果验证。作者与审批人、计算人与验证人必须分别独立；所有定义、提交、批准、计算和验证同时写入业务证据与平台审计日志。

- 总部端：维护公司级指标规范、角色职责和模板口径。
- 代理端：在获授权客户项目中承担独立审批或验证，不得越租户读取事实。
- 客户端：在自己的项目及计划内定义、计算和查看指标，不得通过指标中心修改订单、财务或仓库事实。

所有记录携带 `agent_path`、`tenant_id`、`client_id`、`project_id`，按需携带 `plan_id`，共享发布只同步指标模板与治理规则，不覆盖客户业务结果。

## 运营验收

上线前必须证明：指标代码租户内唯一；口径只引用批准字段；作者不能批准自己的版本；已发布旧版本在新版本上线后进入 `superseded` 且历史结果不重算；未发布或血缘不完整的仓库批次不能计算；计算人与验证人不同；发布结果能够从页面、API、证据和审计日志核对到同一个版本、公式哈希、仓库批次、水位、事实数和维度观察；生产构建和真实浏览器闭环均通过。
