# AI问数与战情中心运营契约

## 业务定位

AI问数与战情中心是只读决策辅助层。首期引擎固定为 `deterministic-governed-retrieval-and-scenario`：它通过受控意图识别读取已发布经营健康、贡献利润、经营预测和风险预警，不调用外部大模型，也不把规则计算包装成生成式AI。每次回答必须固定来源对象、业务编号、修订号、状态、观察时间和内容指纹；没有受支持且已发布的事实时，系统必须拒绝回答，禁止编造。

后续接入大模型时只能增加经过审批的适配器。大模型可负责语言理解和表达，但引用校验、权限、租户隔离、情景公式、审批、交接和审计仍由本契约控制；模型输出不得直接改变任何业务事实。

## 问数与引用

首期支持四类意图：经营健康、贡献利润、现金与产能预测、未关闭经营风险。回答分类固定为 `governed-decision-assistance`，并明确 `external_llm_called = false`。一次问数生成一条查询记录和一至多条不可变引用；同租户的稳定查询引用不可重复。未知意图返回“未支持且未生成回答”，不得降级为无依据的自由文本。

引用只接受对应客户、项目和计划中的 `published` 经营健康快照、贡献利润运行和经营预测运行，或仍为 `open/acknowledged` 的健康预警。回答只展示这些已发布对象的字段，不从草稿、待审批记录、其他租户或浏览器缓存拼接数据。

## 零回写情景模拟

情景必须固定最新已发布经营预测的运行ID、运行号和修订号，再记录需求、产能、现金流入和现金流出变化百分比。模拟订单、产能需求、可用产能、产能余量、现金流入、现金流出和净现金均写入独立情景记录并生成引擎指纹。

情景计算不得修改预测运行、仓库事实、订单、产能资源、采购单、回款或财务记录；`scenario_writeback` 永远为 `false`。若没有已发布经营预测，禁止计算。

## 建议、审批与执行交接

建议必须且只能引用一条治理问数或一条治理情景，包含标题、理由、风险等级、目标系统、责任人和未来截止时间。建议状态机为：

`pending-approval → approved → handed-off → closed`

作者不得审批自己的建议。只有 `approved` 建议才能生成唯一交接记录；交接只保存目标系统和稳定任务引用，不在本应用中伪造ERP、CRM、MES、WMS、SRM、财务、营销或服务系统的业务对象。关闭交接必须提交目标系统的真实执行证据编号，然后同步把建议标为 `closed`。

## 权限、审计与三端边界

权限拆分为问数执行、情景执行、建议管理、建议审批和交接管理五项。所有变更动作都写平台审计，审计必须携带 `project_id`；所有业务记录携带 `agent_path`、`tenant_id`、`client_id`、`project_id` 和 `plan_id`。

- 总部端维护引擎规则、权限模板和目标系统适配标准，不读取未授权客户事实。
- 代理端只可在明确授权的客户项目中承担问数、独立审批或交接角色，不能跨客户取数。
- 客户端管理本项目问题、情景、建议、审批和执行凭证；真正执行数据仍归目标业务系统。

共享发布可以同步页面、规则模板和适配器配置，不能覆盖客户查询、引用、情景、建议、交接和证据。
