# 六大横向平台底座规范

六大底座服务现有十二类业务，不新增第13类。底座只提供公共数据、连接、流程、合规、AI治理和价值交付能力，不拥有询盘、订单、财务、库存等业务事实。

程序事实源为 `FACTORY_PLATFORM_FOUNDATIONS`。底座名称、职责、能力和验收条件调整时，必须先改程序契约，再由规范生成器和构建门禁验证本文。

## 底座职责

| 顺序 | 底座 | 核心职责 | 首次强制阶段 |
| --- | --- | --- | --- |
| 1 | 数据底座 | 主数据、统一对象ID、事件、指标、血缘 | P0 |
| 2 | 集成中台 | API、Webhook、连接器、映射、重试和补偿 | P0 |
| 3 | 流程引擎 | 流程、规则、审批、责任任务和超时升级 | P0 |
| 4 | 合规护栏 | 证照、贸易、隐私、碳数据、追溯和审计证据 | P1 |
| 5 | 智能治理 | 模型、智能体、知识、权限、人工复核、评测和成本 | P2 |
| 6 | 价值交付 | 套餐、授权、计量、实施、验收、续费和价值证据 | P0 |

## 共同技术不变量

1. 所有核心记录携带 `tenant_id`、业务对象ID、来源、版本和时间。
2. 连接器只能在适配层转换外部字段，不得把供应商数据结构渗透进领域模型。
3. 流程状态不得冒充订单、客户、库存或财务事实；流程失败必须具备重试、补偿或人工接管。
4. 合规规则必须按国家、产品、版本和生效时间保存，历史证据不得静默覆盖。
5. AI不得直接改变正式订单、价格、付款、质量放行、招聘录用等高风险状态。
6. 套餐只决定能力授权和交付范围，不改变业务事实源与数据所有权。

## 数据底座对象范围

首批统一对象至少包括：组织、员工、企业客户、联系人、产品、SKU、内容、活动、询盘、商机、报价、合同、确认订单、BOM、批次、库存、发运、发票、付款、客户资产和服务工单。

每个对象必须声明事实源、全局标识、租户边界、版本策略、生命周期事件、允许消费者和数据保留规则。

## 底座验收顺序

1. 先冻结对象、事件、权限和事实源契约。
2. 再实现连接器、流程、审计和监控。
3. 使用真实端到端业务链验证失败、重试、补偿和回退。
4. 最后才允许业务应用把底座能力标为试点或已具备。

底座未通过验收时，业务页面可以保留规划入口，但不得复制一套临时主数据、权限、工作流或AI治理实现绕过底座。
