# 普通页面工厂

普通页面工厂把每次开发都要重复说明的规则固化成代码契约。总部端、代理源、客户源共享同一套标准，页面仍按各自业务归属开发，不复制三份源码。

## 唯一事实源

- `frontend/src/page-factory/page-factory-standard.json`：版本、模板、区域、能力、CSS 插件、恢复边界和发布顺序。
- `frontend/src/page-factory/page-registry.json`：已经接入的页面与源码位置。
- `frontend/src/page-factory/page-command-catalog.json`：开发器显示的可扩展命令。
- `frontend/src/page-factory/factory-default-snapshot.json`：通过全部检查后生成的代码默认快照指纹。
- `frontend/src/page-factory/page-inventory-baseline.json`：代码拥有的只读普查基线，用于发现页面、路由和风险分级变化。
- `tools/page_factory.py`：Python 只读检查与计划优先的登记、版本、快照命令。

## 固定能力

每个正式登记页面必须具备小屏自适应、开发器、可视化、共享契约、恢复工厂默认和版本治理。十一类区域是全平台共享目录；顶部、主体、标题一和尾栏是每种模板的核心区域，标题二、表内、表头、内容、大卡片、小卡片和滚动条由七类模板按真实页面结构选用。没有表格的 dashboard 不伪造表头，没有卡片的 form 不伪造卡片标注。页面只能调用共享 CSS 插件；色卡对比等被明确认定为业务视觉事实的局部样式可以独立，但必须在登记信息中说明，不能绕开可访问性和小屏检查。

恢复工厂默认只恢复代码拥有的布局、区域和契约状态，绝不覆盖业务数据、上传素材、租户内容、下游自定义、数据库或正式备份。

框架归属只有两种：普通页面使用 `factory-shell`，由 `FactoryPage` 创建共享可见外框；已经拥有 `SharedPageWorkspace` 等真实主体的复杂页面使用 `existing-workspace`，由 `FactoryPage asChild` 把页面工厂身份、区域策略和版本合并到现有主体。后一种模式下，页面工厂、开发器主体、可视化主体和共享契约必须命中同一个 DOM 节点，禁止再生成边框、圆角、内边距、阴影或滚动层；也禁止用页面私有 CSS 隐藏重复外壳。

产品市场的分类契约也遵循唯一事实源：栏目配置拥有分类键、共享拖拉／上下移、两位排号和分类名称，分类控制链固定为“拖拉 → 上下移 → 01 → 分类名称 → 开通／取消／隐藏”。拖动或上下移只更新同一份 `moduleCategoryOrder`；左侧栏和运营市场实时读取该顺序并显示同一“01.分类名称”，不得维护第二份分类清单或排序状态。运营市场三个状态按钮只批量设置本分类卡片，并通过现有确认、共享快照提交和回读验证流程保存；分类状态操作不依赖卡片勾选，也不清除其他分类已有选择。左侧栏、栏目配置与运营市场三处分类图标统一读取左侧栏的“专家素材头像 → 已保存头像 → Users 默认图标”解析链。栏目配置分类标题在所有尺寸均保持普通文档流，随所属分类滚动，不吸顶、不固定。

三处设置页与两个投影面共同读取 `shared-sortable-ownership-contract-v3`：栏目配置分类栏、版面风格、客服音效和运营市场分类投影复用一套单胶囊，拖拉／上下移插件固定为 112×32，含排号工具栏固定为 152×32；桌面胶囊统一为 50px 外层、6px 内边距、36px 内容、14px 字号／20px 行高，胶囊到归属内容统一留 12px。只有外层胶囊绘制 1px 边框和 12px 圆角，栏目配置内部操作承载器透明无框，以共享间距分清内容。胶囊默认读取当前版面大卡片底色并混入 24% 字色加深；鼠标进入最近大卡片、运营分类任意位置或键盘焦点进入时加深至 56%，不把整块表单染色。栏目或分类通过稳定归属键连接到运营市场和左侧导航：跨区联动 8%，分类提示 10%；联动不导航、不滚动、不展开、不写入任何配置。栏目配置仍是唯一排序源，运营市场仅是状态管理投影，左侧导航仅是导航投影。总部端、代理源、客户源以及开发器、可视化、运行时学习和恢复工厂默认共同读取 `shared-product-market-category-contract-v5`。

客服音效以“当前专家真人朗音自定义”为唯一事实根，并登记为 `shared-customer-service-expert-content-v1`：选择专家卡、当前专家预览、左侧栏专家弹窗、换专家列表和客服聊天窗口只能投影同一已保存 `csAvatarOverrides`，不得另建客服名称、朗音或招呼词内容仓。编辑器允许把未保存文字草稿投影到当前预览，但左栏与聊天只在保存事件后读取当前端、当前站点的运行时配置。身份事实固定按“名称、头衔、性别”排列，头像仍是媒体而不再占身份字段；分类专家归属名与客服名称分开显示，不使用 `>` 拼成长标题。客服名称、朗音与招呼词共同读取 `single-line-ellipsis-v1`，值区域允许收缩，超长时单行省略并以原生 `title` 保留完整值。专家列表读取 `shared-service-expert-capacity-v2`：单卡可读宽为 416px，内容容器在 840／1264／1688px 依次进入二／三／四个等宽卡片并封顶四列；卡片自身在 415px 与 287px 以下分级重排，列数和卡内重排都不得依赖浏览器视口。专属容量与卡内规则只存在于 `shared-service-expert-capacity.css`，`index.css` 不得再维护第二套专家容量规则。总部端、代理源、客户源、页面工厂根、开发器主体、可视化根、共享契约主体及恢复工厂默认共同读取这一代码拥有的契约。

栏目配置的一级、二级编辑行读取 `shared-module-editor-capacity-v5`：真实栏目卡片是唯一边界，左右布局承载器透明无框；图标设置、状态和展开箭头保留真实控件边界，层级、两位排号和新增层级改用无框文字分段与共享分隔线。总部端、代理源、客户源的 `existing-workspace` 同时作为页面工厂根、开发器主体、可视化根、共享契约主体和恢复工厂默认来源，不允许页面私有样式重新套壳。

页面身份使用“来源端 + 归一化路由”联合键。总部端 `/zb`、代理端 `/dl` 和客户源 `/` 可以拥有相同的归一化路由 `/`，但会分别匹配 `hq`、`agency_source`、`client_source`，不会串用登记信息。

## 日常流程

1. 在开发器的“页面工厂”选择模板和命令。
2. 使用 `python tools/page_factory.py new ...` 或 `adopt ...` 先生成计划；确认后才加 `--apply` 登记。
3. 页面用 TypeScript 的 `FactoryPage` 与共享 CSS 区域插件接入。
4. 运行 `python tools/page_factory.py check --route <route>`。
5. 运行 `npm run verify:page-factory`、TypeScript、ESLint 和相关浏览器测试。
6. 全绿后推进工厂版本，并建立不可变的工厂默认快照。

当前首个试点是“产品分析 → 兴趣搜索”，采用 `workflow` 模板。试点验证通过后，其他普通页面按同一路径渐进接入，禁止一次性机械改写全部页面。
## 第二阶段：只读普查与覆盖率中心

`python tools/page_factory_inventory.py` 只读取 `frontend/src/pages`、`App.tsx` 的字面路由声明和页面工厂登记表，输出稳定的覆盖率、源码特征风险分级和 B01—B03 审查队列；默认不写任何文件。覆盖率、风险数量和 B01—B03 候选都只以已由路由声明直接引用的页面入口为准；辅助页面文件单独列出，不会稀释真实页面覆盖率或混入接入计划。普查还会校验每条字面 App 路由都能追溯到一个页面源码；新增路由而未更新该映射会使验证失败。仅在维护代码拥有的普查报表时使用 `--write-report`，在确认当前普查结果作为新基线时使用 `--write-baseline`；两个目标都位于 `frontend/src/page-factory`，不会写业务页面或受保护数据。

开发器的独立“07 页面工厂”会在总部端、代理源和客户源显示同一份覆盖率中心。它位于 06 质量与发布中心之后、08 页面锁定器之前，用于安排人工审查，不能自动接入、复制、移动或批量改写页面；也不会读取或写入数据库、上传素材、正式备份或外部服务器。每一页仍必须单独获得授权，再执行现有的 `new` / `adopt` 计划、共享契约检查、小屏验证和工厂默认确认。

B01—B03 必须完整覆盖全部未接入路由，且同一页面不得重复进入两个批次。每个风险批次再按固定上限拆成小波次；波次仍只是审查顺序，`single-page-authorized` 表示执行时必须逐页获得授权，不代表可以整波批量改写。

## 真正使用 07 页面工厂

1. 在总部端、代理源或客户源任意页面打开“开发器”，选择独立的“07 页面工厂”。
2. 先看两个独立数字：第二阶段治理完成度表示普查、风险、计划、覆盖率数据和差异基线是否齐全；正式接入覆盖率表示已有多少真实路由完成页面工厂改造。治理达到 100% 不等于全平台页面已经接入。
3. 在“全平台普查明细”按关键字和风险筛选，选择一个页面、准确路由和模板。
4. 复制单页接入计划命令。页面显示的命令故意不含 `--apply`，执行后只预览；只有获得该页面的明确改造授权后，才手动追加 `--apply`。
5. `new`、`adopt` 或版本推进实际使用 `--apply` 后，Python 会自动重写代码拥有的普查报表，因此正式接入覆盖率和版本立即更新。它不会自动接受新基线；出现真实差异时治理完成度会暂时降为 80%，待人工审查后再用 `--write-baseline --write-report` 恢复到 100%。
6. 单页改造完成后运行当前页检查、Python 检查、TypeScript、ESLint、共享契约和小屏浏览器测试；全部通过才确认工厂默认并推进版本。

`adopt --apply` 只把页面标为 `adopting`，不会提前增加正式完成覆盖率。只有全部登记页面检查通过并执行 `snapshot --apply` 后，该页面才转为 `complete` 并计入百分比，防止用空登记或套壳伪造 100%。

页面工厂版本、第二阶段百分比、正式接入覆盖率和普查基线状态会固定显示在 07 页面工厂。后续新增固定规则时，先更新 `page-factory-standard.json`、Python/TypeScript 检查和此文档，再通过 `bump` 与 `snapshot` 固化；不要把规则散落到会话提示词或复制到每个页面。
