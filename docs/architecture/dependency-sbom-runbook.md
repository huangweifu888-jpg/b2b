# Dependency SBOM runbook

Every CI run generates CycloneDX JSON inventories for both application dependency sets:

- `frontend.cdx.json` is generated from the reviewed `frontend/package-lock.json`.
- `backend.cdx.json` is generated by `pip-audit` from the reviewed, exact `backend/requirements.lock.txt`.

The workflow uploads these files as the `b2b-dependency-sbom` artifact. They are build evidence, not source files; do not commit generated SBOM output or dependency caches.

From the repository root, generate a local frontend inventory with the active
Python interpreter:

```powershell
python .\tools\generate_frontend_sbom.py --output (Join-Path $env:TEMP 'b2b-frontend.cdx.json')
```

For the backend inventory, use the isolated CI environment or an idle backend virtual environment with `pip-audit` installed. Treat an SBOM as an inventory, not an approval: review it together with the dependency audit and the time-limited exception policy before releasing an artifact.
