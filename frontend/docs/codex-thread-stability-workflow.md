# B2B 稳定性工作流

本项目不使用“自动续跑”或任何隐式恢复循环。每一项开发由明确请求或当前目标推进，并在源码、实际页面与构建三个层面留下可验证结果。

## 固定顺序

1. 读取当前页面、共享变量和内容设计的归属。
2. 先修复异常隔离、路由、容器或旧框架问题。
3. 仅对当前范围进行可恢复修改。
4. 检查页面清扫器规则、首页大图基线和相关页面契约。
5. 执行 `npm.cmd run build`。
6. 通过后写入版本记录和已确认学习记录；失败则保留现场并修复，不覆盖配置。

## 稳定性边界

- 右侧沙盘异常必须被局部错误边界隔离，不能替换整个业务页。
- 本地环境提醒先做健康检查；全停时提供启动，部分异常时提供重启，并显示失败原因。
- 布局开发器在外置工具菜单内按需加载；历史与预览仅在用户打开工作区后加载。
- 页面锁定只保护页面结构，不冻结共享变量的主题令牌。
- 下游页面不得反写模板源；同步不得覆盖下游自定义和新增业务数据。

## 验证基线

首页设计 → 首页大图为普通业务页基线，验证真实列表、内容插件操作、滚条、尾栏和共享框架。产品市场 → 运营市场为主框架基线，验证主体、标题、表头、内容、尾栏和右侧栏令牌。

## 版本与恢复

外置开发工具只保留最近 10 个本地快照。恢复动作必须明确确认，恢复后必须重新构建；构建通过才可将结果视为可复用学习记录。
