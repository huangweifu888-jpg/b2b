# 总部、双源、实例与模板快照架构

本架构采用“一份程序源码、两条受控模板来源分支、多个隔离运行实例”。程序发布与模板同步是两件不同的事：程序由七角色构建规则发布，模板只发布版本化配置、内容结构、品牌参数和受控素材引用。

当前目录和服务器事实以 [源码入口](../../README.md) 与 [部署中心](../../deployment/README.md) 为准。

## 1. 固定角色

### 总部端、代理源、客户源

三者共同属于角色 `01-hq-source-control`：

- 总部端维护平台标准、租户注册、共享契约和发布控制。
- 代理源维护允许发布给代理端的模板与配置版本。
- 客户源维护允许发布给客户端和客户计划的模板与配置版本。
- 代理源与客户源互不发布，也不能绕过来源端直接覆盖另一条运行分支。

### 代理端

代理端属于角色 `02-agency-runtime`：

- 只接收代理源已发布的允许内容。
- 使用 `agent_path` 和 `tenant_id` 隔离多代理、多级代理。
- 保存代理实例自己的快照和允许的覆盖项，不复制应用源码。

### 客户端与多个计划

客户端及其计划属于角色 `03-client-plan-runtime`：

- 只接收客户源已发布的允许内容。
- 使用 `agent_path + tenant_id + client_id + plan_id` 隔离。
- 每个计划保存独立配置、内容、品牌、域名绑定和素材引用，不复制客户端应用。

角色 `04`—`07` 分别提供异步任务、公网入口与观测、数据服务、备份与灾难恢复，不建立新的模板来源分支。

## 2. 唯一源码与交付区

| 相对位置 | 作用 |
|---|---|
| `00-platform-source` | 唯一可编辑程序源码 |
| `00-platform-source/zbcx` | 总部应用壳 |
| `00-platform-source/dlcx` | 代理应用壳 |
| `00-platform-source/khcs` | 客户应用壳 |
| `00-platform-source/modules` | 可复用业务模块 |
| `00-platform-source/shared` | 共享契约和公共边界 |
| `00-platform-source/deployment/role-definitions` | 七角色程序打包规则 |
| 外层 `01`—`07/releases/<version>` | 经审核的不可变角色程序成品 |
| 外层 `local-data` | 本机数据库、素材、预览和恢复暂存 |
| 外层 `local-runtime` | 可重建的本机运行时和依赖 |

外层七角色不是源码目录。程序缺陷必须回到 `00-platform-source` 修复并重新发布，禁止在运行服务器或角色成品中直接修改。

## 3. PathRegistry 与数据位置

源码只保存工作区相对的 PathRegistry 示例；当前电脑的机器配置位于工作区 `local-data/config/path-registry.json`。工作区移动后由根目录重新解析，不以盘符作为身份。

当前本地逻辑位置：

| 数据类型 | 工作区相对位置 | 上线边界 |
|---|---|---|
| 沙盘数据库 | `local-data/database/platform.sqlite3` | 仅本地；生产改用角色 `06` 的 PostgreSQL |
| 私有素材 | `local-data/objects/asset-private` | 生产改用私有对象存储或私有挂载 |
| 站点预览 | `local-data/site-public` | 只存本地公开预览成品 |
| 网站风格模板 | `00-platform-source/shared/contracts` | 由共享契约维护，并随角色 `01` 的受控模板清单发布 |
| 本地备份暂存 | `local-data/backup-staging` | 不等于角色 `07` 的异地备份 |
| 本地发布证据 | `local-data/release-artifacts` | 不等于外层七角色正式版本成品 |

生产数据按 `control`、`agency-runtime`、`client-plan-runtime`、`ops-audit` 逻辑域治理。默认不为每个代理、客户或计划复制数据库文件；只有合同、安全或容量证据要求时，才通过批准的 `deployment_id` 和 `database_id` 分配独立运行单元。

## 4. 模板、版本与实例

### 模板

模板保存：

- 页面结构和模块开关
- 版面风格和品牌变量
- 默认内容与多语言结构
- 受控素材引用及权利信息
- 兼容程序版本、来源分支和发布状态

模板不保存客户业务数据库、上传素材原件、密钥、日志或程序目录副本。

### 模板版本

每次发布生成不可变模板版本，至少记录：

- 模板 ID、来源分支和版本号
- 兼容程序版本
- 配置快照、变更说明和校验值
- 发布人、发布时间和审核记录
- 回滚版本和影响范围

### 运行实例

实例保存自身绑定的模板版本、当前快照、允许的覆盖项、同步状态和审计记录。代理、客户端和计划实例只在明确操作后同步，不实时硬读上级正在编辑的草稿。

## 5. 两条发布分支

```text
总部端
├─ 代理源已发布模板 → 代理端/下级代理实例
└─ 客户源已发布模板 → 客户端 → 客户计划实例
```

同步只能沿所属分支向下进行。总部端不能跳过代理源或客户源直接覆盖实例；代理源与客户源不能横向同步。

## 6. 页面操作语义

### 保存设置

- 只保存当前模板草稿或实例快照。
- 不自动发布，也不回写上级来源。

### 发布新版

- 先生成差异、影响范围和恢复点。
- 审核通过后创建不可变模板版本。
- 不自动覆盖所有运行实例。

### 同步最新版

- 由实例主动选择所属来源的已发布版本。
- 同步前显示差异、冲突、数据边界和回滚版本。
- 只更新允许同步的配置与内容，不覆盖业务数据和素材原件。

### 恢复工厂默认

- 恢复到当前程序版本登记的工厂模板快照。
- 操作前生成实例恢复点并显示影响。
- 不复制源码，不替换数据库，不删除客户业务数据。

### 脱离与重新接入

- 脱离只停止后续模板同步，实例仍使用同一程序角色版本。
- 重新接入必须选择明确的来源模板和版本，并先完成差异预演。

## 7. 程序发布与模板发布的关系

程序发布遵循 [全局六步流程](../../deployment/common/global-release-flow.yaml)：预检、选择服务器组合、生成角色包、审核影响、部署、健康检查与回滚。

模板发布必须声明兼容的程序版本。程序升级不会自动修改客户业务数据；模板同步也不会替换角色程序包。只有两者兼容且各自通过门禁，实例才允许进入新组合。

## 8. 数据与备份

- 本地 SQLite 只用于沙盘和验收。
- 生产 PostgreSQL、Redis 和对象存储由角色 `06` 提供。
- 正式备份由角色 `07` 写入不同服务器、凭据和故障域。
- 模板版本、实例快照、程序版本和数据库备份分别记录，但由同一发布/恢复记录关联。
- 恢复演练只能在隔离环境执行，不能覆盖生产实例。

## 9. 前后端职责

Python 负责模板版本、实例快照、差异、同步任务、租户授权、审计、数据库迁移和恢复门禁。TypeScript 负责三端管理界面、差异预览、确认流程、状态展示以及桌面与小屏自适应。

前后端共同读取共享契约和事实源，不在页面、脚本或文档中再建角色名称、目录或模板状态副本。

## 10. 固定原则

1. 一份程序源码，七个部署角色，不复制七套源码。
2. 模板是版本化配置和内容契约，不是程序目录快照。
3. 实例自定义只写自身覆盖层，不回写上级来源。
4. 模板发布、程序发布和数据库迁移分别审核、共同关联。
5. 数据、素材、密钥和备份不进入应用角色包。
6. 路径由工作区根、PathRegistry 和部署环境解析，不写死电脑路径。
7. 所有同步、恢复和回滚都必须留存差异、审批和审计证据。
